# 複合候補の探索範囲診断（2026-09-09）

外部比較でAnthyだけが正解し、Slimeの上位10候補に正解がなかった4問を調べた。4問とも `is_exact_segmented_surface` がtrueであり、現在の辞書の要素をつなげれば正解表記を構成できる。単純な構成語の欠落ではない。

| 入力の要点 | 初めて確認できた探索上限 | その探索での正解順位 |
| --- | ---: | ---: |
| エンジェル隊に復讐と称して色々なちょっかい | 32 | 27 |
| ダルマリーの事件終結当夜 | 512 | 427 |
| 対空機銃群 | 32 | 16 |
| 弱冠十三歳にし | 512 | 146 |

探索上限10・32・128・512を同じ辞書で実行した。表は試した上限のうち正解が現れた最小値であり、出現する最小設定値を厳密に探索したものではない。返される候補数には最後の読み候補も含むため、指定上限に1が加わる場合がある。これは直接converter APIの候補であり、実際のSpace候補には追加の再結合処理などもある。

コスト最小経路では「対空機銃群」が「タイ＋空気＋従軍」に分割され、「復讐と称して」が「復讐＋渡渉＋し＋て」に分かれていた。正しい候補を単語の追加だけで解決しようとすると、既存語の重複や例文への過剰な調整につながる。

診断用の単発Release計測では、上限10は約3.5〜11.6ms、32は約19.9〜43.5ms、512は約4.5〜9.6秒だった。反復測定ではなく一般的な速度比較には使えないが、広い探索をそのまま製品に入れられないことは明らか。この変更は製品へ採用していない。

次の検討箇所は `insert_n_best_node` の候補保持処理。各候補挿入時にbucket全体を走査して重複・同一右品詞の最悪候補・全体の最悪候補を調べるため、探索上限を広げる際の処理量が増える。改善する場合は、品詞接続・同コストの選択順・重複判定を保った上で、同一出力と反復計測を確認する必要がある。

再現資料は `target/evaluation/compound-frontier-20260909/`。独立したRust診断プロジェクト `probe/` は現在のconverterをpath dependencyとして参照する。`run.py`、各例のテキスト出力、`build.log` を保存した。製品ソースとQAアプリには変更を加えていない。
