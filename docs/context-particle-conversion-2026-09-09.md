# 文脈学習を助詞付きのSpace変換に反映 — 2026-09-09

「食事」の後の「はし」を「箸」と繰り返し確定した学習が、「はしを」「はしに」などの
Space変換にも反映されるようにした。モデルを有効にした更新アプリで、
「橋を→箸を」「橋に→箸に」を含む9種類の助詞を確認した。

## 条件と変更

対象は読みの末尾が「は・が・を・に・で・と・も・へ・の」の場合。
助詞を除いた読みについて、現在の文脈に一致する繰り返し学習があり、
学習済み表記と助詞を合わせた表記が既存の辞書候補に含まれる場合のみ優先する。
候補に存在しない表記を新しく追加する変更ではない。

候補のメタデータも学習由来として扱い、モデルによる上書きから保護する。
入力補正が学習済み候補を押し下げる経路も、既存の完全一致の学習と同様に抑制した。
ユーザー辞書や、全文で記録済みの通常履歴の優先順位は維持した。
保存形式・学習回数の条件は変更していない。

## 同梱物での確認

新しい検証用ディレクトリに保存した文脈学習を使用し、ローマ字をC APIへ入力した。
モデルは同梱のQ3_K_Mで、読出し時の学習は無効にした。

| 読み | 変更前 | 変更後 |
| --- | --- | --- |
| はしは | 橋は | 箸は |
| はしが | 橋が | 箸が |
| はしを | 橋を | 箸を |
| はしに | 橋に | 箸に |
| はしで | 橋で | 箸で |
| はしと | 橋と | 箸と |
| はしも | は下 | 箸も |
| はしへ | 橋へ | 箸へ |
| はしの | 橋の | 箸の |

9件とも学習由来の候補値・メタデータを確認した。文脈リセット後とプライベートモードでは
学習由来のメタデータが付かないこと、検証用履歴の内容が変わらないことも確認した。
Coreの追加テストでは、候補にない表記を作らないことと「ご」のような助詞でない末尾を除外することを確認した。

Core全237テスト、clippy、C ABI smoke、Swift adapterが成功。
clippyは既知の別箇所の `chunks_exact_to_as_chunks` のみ許可した。
更新アプリの署名検証も成功。インストール、InputMethodKitの実キー入力、公開は未実施。
