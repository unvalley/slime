# 外部変換エンジンとの比較（2026-09-09）

現在のSlimeの明示変換第一候補を、[Anthy Unicode](https://github.com/fujiwarat/anthy-unicode)の既定分節・各文節第一候補と比較した。対象は既存評価集合のうち、もともと前文脈が空の412問。期待表記との文字列完全一致で集計する。

| 集合 | 問題数 | Slime正解 | Anthy正解 | Slimeのみ正解 | Anthyのみ正解 |
| --- | ---: | ---: | ---: | ---: | ---: |
| JWTD | 312 | 141 (45.2%) | 25 (8.0%) | 122 | 6 |
| AJIMEE | 100 | 76 (76.0%) | 20 (20.0%) | 59 | 3 |
| 合計 | 412 | 217 (52.7%) | 45 (10.9%) | 181 | 9 |

## 条件

- Anthy Unicodeのソースリビジョンは `6ec95b51ec6dc11cc3ebeab8cec35d8ccc9dd9d9`。Mesonで付属辞書を生成し、評価ディレクトリにだけビルド・配置した。製品への組み込みやシステムへのインストールはしていない。
- AnthyはUTF-8指定、問題ごとに新規context、既定の分節を使用。各文節の候補0を連結する。候補選択のcommit APIは呼ばない。ライブラリ設定のHOMEとXDG_CONFIG_HOMEを評価用ディレクトリに向け、実際の利用者の履歴を参照しない。
- Slimeは現在の統合検証用バイナリと同じモデル。明示変換の重みは通常0.2、20文字以上0.4。履歴補完・学習は無効、追加辞書パックは0。問題ごとに新規engine。既存の全件評価から抽出した結果を、抽出集合の再実行でも412問すべての出力が一致した。Anthyも2回の実行結果が一致した。
- 入力のカタカナを両者とも同じ範囲でひらがなに変換。期待出力は変更しない。集合は結果を見る前にcontext_textが空である条件で抽出した。
- 速度比較ではない。Slimeはニューラルモデルを使うため、精度差と計算資源の差を分けて解釈する必要がある。

## 限界と次の調査対象

既存評価集合はSlimeの改善時に参照済みであり、新規holdoutではない。モデルの学習データとの重複も証明できていない。単一の公開エンジンとの比較であり、他の市販IMEや実際の入力操作を含む「日本随一」の根拠にはならない。表記の違いも不正解に数える。

Anthyだけが正解した9問を `anthy-only.json` に保存した。例として「司法省に勤め」（Slimeは「努め」）、「生体パーツ」（「整体」）、「対空機銃群」（「軍」）がある。一方、「充分／十分」「十三歳／13歳」のような表記差も含まれる。これらを一律に辞書追加するのではなく、候補不足と順位の問題を切り分ける。

## 不一致9問の候補・スコア診断

同じ候補生成方針の保存済み上位10候補を照合した。5問は正解表記を含み、4問は含まない。この4問は「全辞書に存在しない」という意味ではなく、上位10候補の範囲で不足している。

現在のソースから `debug_neural_score` をビルドして、正解を含む5問を再採点した。結果は `score-*.txt` と `ranking-diagnosis.json` に保存した。

| 問題 | 診断 |
| --- | --- |
| 司法省に勤め | 辞書コスト・モデルとも「努め」を支持。重みだけでは2候補間の逆転はできない。 |
| 生体パーツ | モデルは「生体」を支持。2候補だけなら重み約0.230を超えると逆転する。現在は短文の0.2。 |
| 出会った当初 | 辞書コスト・モデルとも「であった」を支持。前文脈なしでは曖昧さも残る。 |
| 充分だった | 辞書コスト・モデルとも「十分」を支持。完全一致評価上の表記差。 |
| 多変数複素関数論 | モデルは「関数」を支持。2候補だけなら重み約0.420を超えると逆転する。現在は長文の0.4。 |

これらの閾値は保存した候補集合のスコアから計算した診断値であり、製品設定の推奨値ではない。候補数、他候補の順位、全体の回帰を含む実エンジン検証が必要。

## 長文の明示変換重み0.45の実験

製品の既定値は変更せず、現在の評価バイナリに `--explicit-long-lambda 0.45 --explicit-min-characters 20` を指定して1,254問を再実行した。通常重み0.2、LIVE設定は従来どおり。

| 集合 | 現行0.4 | 実験0.45 | 正解への改善 | 正解からの悪化 |
| --- | ---: | ---: | ---: | ---: |
| JWTD 400 | 179 | 180 | 1 | 0 |
| UD dev 331 | 279 | 279 | 0 | 0 |
| UD test 323 | 271 | 271 | 0 | 0 |
| AJIMEE 200 | 138 | 139 | 1 | 0 |

「東京・中国映画習慣→週間」「多変数複素環数論→関数論」が完全一致に改善した。計8問の出力が変化し、うち5問は変化後も完全一致しない。1問は許容される数表記の間で変化した。LIVEの変更トレースとworker status集計は各集合で同一だった。

`explicit045-comparison.json` に全差分、`*-explicit045.json` に全件結果を保存。これは採用前の実験であり、追加の200問による検証と実際のバンドルへの反映・確認はまだ行っていない。この実験時点のQAアプリは重み0.4のまま。


## 追加200問の検証と採用

既存400問とID・原文・読みが重複しない追加200問を、同じ現在バイナリで0.4と0.45の両方を再実行した。完全一致は74→77、改善3、悪化0。変化したのは「前進と確率→確立」「博士後期課程終了→修了」「手法として…習った→倣った」の3問だけだった。LIVE変更トレース・worker status集計は同一。詳細は `expanded-comparison.json`。

計1,454問で完全一致941→946、改善5、悪化0を確認し、`scripts/build-macos.sh` の `SLIME_NEURAL_EXPLICIT_LONG_LAMBDA` の既定値を0.4から0.45へ変更した。対象は20文字以上の明示変換。環境変数による上書きは従来どおり。

モデル同梱のQAアプリを再ビルドし、Info.plistの0.45とアプリの署名を確認した。旧アプリを `Slime-before.app` に保存している。これはローカルのad-hoc署名アプリであり、インストール・公証・公開はしていない。追加200問も既知のコーパスからの抽出であり、モデル学習データと独立したholdoutを証明するものではない。

バンドルのInfo.plist・モデル・dylibを使うSwift検証でも、旧設定の「複素環数論」「博士後期課程終了」が新設定で「複素関数論」「博士後期課程修了」に変わることを確認した。`policy-before-verified.log` と `policy-after-verified.log` に記録。最初の検証コードは読みを「はかせ」から「はくし」に変えてしまっていたため、原データと一致させて再実行した。これはSwiftアダプタまでの検証であり、物理キー入力・InputMethodKitの検証とは異なる。
