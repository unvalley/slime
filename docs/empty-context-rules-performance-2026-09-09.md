# 文脈ルールが空の場合の探索省略（2026-09-09）

インストール済み辞書パックに文脈ルールがなくても、文脈候補の昇格処理がN-bestを再生成し、候補注釈も辞書候補を生成していた。ルールの有無をストアから問い合わせ、空の場合だけ両方を省略する。ルールがある場合の処理は従来どおり。直前文脈が空でも文中のルールは適用され得るため、直前文脈の空白だけでは省略しない。

現在の設定で1,654問を再実行し、明示変換の各出力、LIVE変更記録、worker status集計、正解数がすべて変更前と一致した。コア238件のテストとClippyが通過した。テストには文脈ルールだけを持つv3辞書パックの候補昇格も含む。

同じ長さ別60問を変更前後で交互に3組実行し、各版・反復間の出力一致も確認した。

| Space処理指標（3反復の中央値） | 変更前 | 変更後 |
| --- | ---: | ---: |
| p50 | 36.23ms | 23.11ms |
| p95 | 126.54ms | 70.24ms |
| 最大 | 170.27ms | 86.76ms |

長さ1〜9、10〜19、20〜39、40文字以上から各15問の固定抽出。文脈ルールのない評価環境での結果であり、文脈ルール入りパックがある場合へ一般化しない。計測は評価器のSpace処理区間で、物理キー入力から画面反映までの時間ではない。候補数は10のまま。

資料は `target/evaluation/empty-context-rules-20260909/`。変更前ソース、差分、テスト・Clippyログ、全件結果と比較、`latency/` の入力・全反復・集計を保存した。速度比較スクリプト中の `wide` は再利用したラベルで、この実験では候補数を増やした版ではなく最適化後を指す。

モデル同梱のQAアプリを再ビルドし、署名とSwift経由の代表例2件を確認した。旧アプリは `Slime-before.app`、検証ログは `bundled-probe.log`、ハッシュは `sha256.json`。ローカルad-hoc署名であり、インストール・公証・実機キー入力は未検証。
