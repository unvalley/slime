# Space専用の評価閾値を採用（2026-09-12）

固定かな2,745件でSpaceの完全一致が1,688→1,698（改善10・悪化0）、LIVEは1,698で出力と状態を維持した。調整時に使った追加200件は97→100、新しく長さ4層から選んだ200件は97→99で、いずれも正解の悪化0。QAアプリの確定まで確認し採用した。

## 仕組みと互換性

既存の共通コスト差上限は1,000に保ち、Spaceに限って1,500へ上げる。旧閾値なら評価を省略していた要求では、モデルが選んだ第一候補のひらがな部分列（U+3041〜U+3096）が辞書第一候補と一致する場合だけ適用する。一致しない場合は従来の候補順と表示を維持する。元から評価対象だった要求には追加制約を課さない。

これにより「誕生とし→誕生年」の悪化を防ぎ、「旧制」「実戦」「ご感想」「要員」「自機」「諮られる」「収用」などの改善を保った。候補数、辞書、モデル、ランキング重みは変更していない。前のSpace再結合と適用時の再探索削減も維持している。

新しいC API `slime_set_explicit_neural_cost_gap` は、ロード済みモデルに対する非負の閾値を設定する。既存APIだけを使う呼び出し元は旧動作のまま。LIVEの閾値は変えず、モデル再ロードでこの上書きは解除される。負の値・null・未ロード状態は対応するステータスで拒否する。

評価CLIには `--explicit-max-cost-gap` を追加した。QAのInfo.plistは `SlimeNeuralMaxCostGap=1000`、`SlimeNeuralExplicitMaxCostGap=1500`。Swiftアダプターはこの設定をSpace専用APIへ渡す。コンストラクターで重みやコスト差を明示指定した場合は、バンドルの専用上書きを自動適用しない。

ビルド時は `SLIME_NEURAL_EXPLICIT_MAX_COST_GAP` が最優先。その指定がなく `SLIME_NEURAL_MAX_COST_GAP` が明示されている場合は、その既存の指定をSpaceでも尊重する。両方未指定なら共通1,000・Space1,500。新しい環境変数の不正値はバンドル変更前に拒否する。

## 評価

| 集合 | 件数 | Space 前→後 | 正解の改善 / 悪化 | LIVE |
| --- | ---: | ---: | ---: | --- |
| 固定かな | 2,745 | 1,688→1,698 | 10 / 0 | 1,698で全出力・状態一致 |
| 調整時の追加かな | 200 | 97→100 | 3 / 0 | 全出力・状態一致 |
| 新しい長さ別検証 | 200 | 97→99 | 2 / 0 | 全出力・状態一致 |
| ローマ字 | 200 | 110→112 | 2 / 0 | 109で全出力・状態一致 |

ローマ字集合は固定かなと重なるため独立した改善として合算しない。新しい200件は1〜9・10〜19・20〜39・40〜80文字から50件ずつ、現在の13評価集合と正規化入力が重ならないものを固定seed/IDのSHA256順で選択した。期待出力を選択に使わず、前文脈も実際の入力どおりに渡した。モデル学習データからの独立は保証しない。

完全一致に至らない出力変化も残る。固定かなでは9件、新しい200件では1件で、全差分を保存している。「正解の悪化0」はこれらの入力がすべて改善したという意味ではない。新しい200件では「旧姓」「クビ」が正解になり、「変わって→代わって」は期待表記の「代って」と一致しないため改善数には含めていない。

## 処理時間

固定60件を前後交互に3回ずつ実行した。各回のSpace指標の中央値はp50 24.16→26.76ms、p95 113.39→105.15ms、最大155.03→170.07ms。中央値・最大値は増え、p95は下がった。ばらつきのある測定であり、速度向上を主張しない。モデル評価の追加費用を伴う精度改善として採用した。ビルドと全件評価が終わってから測定し、各版の出力が反復間で一致することを確認した。実機キー入力のUI遅延ではない。
