# 承認済みの動詞・助動詞LIVE候補をSpaceへ引き継ぐ試作

2026-09-14。検証中、未採用。通常版は [採用版GのLIVE改善](live-object-auxiliary-integration-2026-09-14.md)。

Gでは「この商品を買いたい」「この犬を飼いたい」などのLIVE表示とEnter直接確定が改善したが、Spaceを押すと「解体」へ戻る4例が残った。Spaceの協調処理だけにログを入れた最初の診断はGの50件の全出力を再現したものの、この4例のログは出なかった。入口へ記録を追加した診断でもGの出力を完全再現し、実際の原因を確認した。

4例とも直前の正しいLIVE表示がSpace処理へ渡り、正しい候補も辞書候補集合内に存在した。一方、Spaceの採点ゲート1500に対して最小コスト差が1547あり、モデル採点が始まっていなかった。商品では解体12342、買いたい13889、飼いたい14862。犬では解体13352、買いたい14899、飼いたい15872。Spaceの実際のスコアは存在しないため、スコアの強弱による敗北とは扱わない。なお、既存のLIVE協調には漢字以外の文字列を維持する制約もある。

試作ではLIVE適用時に、Gの品詞と本文・終端込みスコアによる承認の有無を既存の選択記録に保持する。Space直前の同じ排他的なエンジン参照から、現在の入力世代・読み・表示と一致する場合だけその承認の読みを取得する。

Space側でモデル採点を省略する場合に限り、承認の全文読みが変換要求と一致し、直前の表示が既存の候補集合にあることを確認して、その候補を先頭へ移す。候補の追加や辞書コストの書き換えはしない。Spaceが通常どおりモデル採点する場合は、今回の引き継ぎを使わず従来の順位付けへ進む。一般の漢字・ひらがな保護条件は変更しない。既存のLIVE協調設定を無効にした場合も引き継がない。

成果物: `target/evaluation/live-auxiliary-space-proof-20260914/`。2段階の診断、50件の出力再現、入口のコスト・候補、試作前後のCore/FFIソース、テスト付きビルド・復元スクリプトを保存している。採用判断には広いコーパス、macOSの両入力順、Space→EnterとLIVE→Enter、追加の採点が生じないことと処理時間を確認する。


最初の候補版はCore271件、変換器69件（既存の無視1件）、neural有効FFI62件・無効FFI61件、tools14件とClippyを通過した。診断50件ではSpaceが42/50→46/50の4改善・0悪化となり、LIVE46/50と全出力を維持した。事前作成の別動詞30件はLIVE・Spaceとも28/30で全出力が同一。既存の協調設定を無効にした4件でもGと全出力が一致し、試作の引き継ぎが働かないことを確認した。
