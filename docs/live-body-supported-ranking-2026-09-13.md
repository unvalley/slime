# 本文の支持を確認する LIVE ランキングの採用

最新状態（2026-09-14）：この LIVE 改善に加え、[本文支持を要求する Space 条件](live-space-body-support-2026-09-13.md)も採用した。以下は LIVE 改善を採用した時点の記録。

2026-09-13。LIVE 案 D をソースと `target/macos/Slime.app` に適用した。インストール・公開はしていない。Space 案 E は未採用で、D と同時に適用した結果は未検証。

## 変更

通常のランキング結果を基準に、モデルの本文スコアも支持する表記変更を追加で選べるようにした。候補の本文と終端の対数尤度を分け、追加の並べ替えでは終端の重みを半分にする。既存の推論結果を再利用し、この追加判断のためのモデル呼び出しは増やさない。

元のモデル重みが .6 以上 .8 未満、読み 4 文字以上、通常ランキングが結果を返す場合に限定する。追加順位付けのモデル重みは .8、切替マージンは .5 以上。選択候補の本文スコアも通常結果を .5 以上上回ることを要求する。非漢字列を保持し、独立した複数箇所の表記変更を制限する。既存の候補幅・コスト・安定部分・接尾部再試行・最終後処理の検証は維持する。

## 精度と動作

| 比較 | LIVE 改善 / 悪化 / その他変更 | Space 改善 / 悪化 / その他変更 |
| --- | ---: | ---: |
| 既存の評価 5,745 行 | 98 / 9 / 45 | 2 / 0 / 1 |
| 条件固定後の追加 400 行 | 6 / 0 / 1 | 0 / 0 / 0 |
| macOS まとめ入力 520 行 | 104 / 9 / 49 | 2 / 0 / 1 |
| macOS 一文字入力 520 行 | 102 / 10 / 43 | 2 / 0 / 1 |

改善・悪化は期待表記との完全一致による分類。既存 5,745 行にはかな・ローマ字の重複表現がある。追加 400 行は既存入力と正規化した読みが重ならず、出力を使わない固定規則で選んだ。モデルの学習データから独立しているとは主張しない。macOS の 520 行は変更例と対照例を集めた集合であり、一般的な利用分布とは異なる。

改善例には「陰湿な正確→性格」「メンバーを語った→騙った」「紫綬褒章受賞→受章」がある。一方、「電波の型式→形式」「更生プログラム→構成プログラム」などの誤変換が残る。悪化ゼロの変更としては扱わず、広い比較と追加対照での改善を踏まえて採用した。

macOS の両入力方式で、直接 Enter 190 行ずつは LIVE 表示どおりに確定した。Space と Enter の再生でも確定文字列の検証を通過した。Swift の `RustEngine` と実際の FFI ライブラリを通る再生であり、実際の InputMethodKit ホストアプリで物理キーを入力した検証ではない。一文字入力での表示変更回数の中央値は 5 回から 6 回に増えた。

## 速度

アプリと同じ明示変換設定（実験的 recombination は無効）で、同じ 268 行を基準版・D・E の順序を入れ替えて各 3 回測定した。各版の反復で出力が一致した。下表は各回のパーセンタイルの中央値、単位 ms。

| 段階 | 基準版 | D |
| --- | ---: | ---: |
| worker p50 | 43.532 | 40.510 |
| worker p95 | 93.739 | 83.982 |
| snapshot p95 | 0.003750 | 0.004666 |
| apply p95 | 0.021291 | 0.031125 |
| Space p95 | 109.958 | 105.402 |

apply の各回最大値の中央値は 0.943ms→2.789ms。通常設定で大きな遅延増は観測されなかった。別の初回測定では、評価器専用の recombination を有効にした条件で D に遅延増があった。測定間には端末負荷などの差もあるため、設定変更だけを原因と断定せず、一般的な高速化も主張しない。モデル読み込みと物理キー入力から画面描画までの時間は対象外。
