# ライブ変換

Slimeのライブ変換は、入力全文を毎回無条件に第一候補へ置き換える機能ではない。
一度表示した有用な接頭辞を維持し、未確定または曖昧な末尾だけを読みのまま扱う。

## UXの契約

- 未確定ローマ字をかな漢字変換のラティスへ入れない。
- 末尾が曖昧になっただけで、変換済みの接頭辞をかなへ戻さない。
- Enterは、その時点で画面に表示されているmarked textと同じ文字列を確定する。
- Escapeで読みへ戻した後は、現在のcompositionが終わるまでライブ変換を再開しない。
- ライブ表示をEnterで確定しただけでは学習しない。Space後の候補選択や補完候補の選択は学習する。
- Spaceによる明示変換ではライブ変換の信頼度閾値を使わず、通常の候補一覧を提示する。

期待する遷移の例:

```text
日本 → 日本g → 日本語
今日は → 今日はいい
そう → そうs → そうしま → そうしましょう
```

## 状態と判定

`slime-core`は、ライブ候補が覆う読みとその表記を`LivePreview`として保持する。
新しい入力全体を変換できない場合も、現在の読みが以前の読みをprefixとして含むなら、
以前の表記へ新しい末尾をそのまま連結する。

辞書候補は通常2経路だけ探索する。上位2経路が同じ表記なら、内部の分割差を
ユーザーに見える曖昧さと誤認しないよう4経路まで適応的に広げ、異なる表記同士を比較する。
第一候補と次の異なる表記のコスト差が500未満なら、新しい全文候補は採用しない。

ユーザー辞書の完全一致は常に優先する。入力履歴は、旧バージョンで暗黙確定された
誤変換を再表示する可能性があるため、ライブ変換には使用しない。履歴はSpace後の
変換候補と補完候補の順位付けにだけ使用する。

## 既知の限界

現在の既定rankerは、単語コストと品詞接続コストだけを使う。左文脈や文の意味を
理解しないため、`制度/精度`、`漢字/感じ`、`箸/橋`のような同音異義語を
信頼度閾値だけで正しく選ぶことはできない。

接頭辞保持は表示の巻き戻りを減らすが、以前の候補と新しい候補が十分な差で入れ替わる場合の
書き換えまでは禁止しない。将来の文脈rankerでも、精度だけでなく次を評価する。

- 変換済み接頭辞のrollback回数
- 同じ範囲での表記の往復回数
- ライブ候補を訂正するためのSpace、候補移動、Backspaceの回数
- 暗黙確定が履歴へ与える影響
- 10、50、100文字での1キー平均とp95 latency
