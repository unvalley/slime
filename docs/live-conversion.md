# ライブ変換

Slimeのライブ変換は、入力全文を毎回無条件に第一候補へ置き換える機能ではない。
未確定の末尾を評価し、後続入力でも維持された文節はmarked textに残したまま
以後の変換対象から外して、変換対象を右へ進める。

## UXの契約

- 未確定ローマ字をかな漢字変換のラティスへ入れない。
- 未確定ローマ字から新しい信頼できる全文候補が作れない間だけ、かな読みが変わっていない範囲の変換結果を保持する。
- 新しい全文候補の差が閾値未満でも、上位経路のいずれかが直前の変換結果と新しいliteral suffixの連結に完全一致し、1位との差が同じ閾値内なら安定した拡張として採用する。
- 内容語だけでは固定せず、助詞まで含む信頼できる文節が後続入力でも維持された時点で遅延固定する。
- 固定済み文節は未確定のmarked textに残すが、後続キーの変換対象には含めない。
- 固定前の範囲が曖昧なら、古い変換と新しい末尾を機械的に連結せず、その範囲の読みへ戻す。
- Enterは、その時点で画面に表示されているmarked textと同じ文字列を確定する。
- Escapeで読みへ戻した後は、現在のcompositionが終わるまでライブ変換を再開しない。
- ライブ表示をEnterで確定しただけでは学習しない。Space後の候補選択や補完候補の選択は学習する。
- 5文字以上の完全一致フレーズをSpace後に明示的に選び直した場合は、同じengine session内の次回入力から即時反映する。再起動後も反映する永続履歴は従来どおり2回以上を要求する。どちらも通常候補と同じ上位10経路に残り、第一候補とのコスト差が2500以内の表記だけを対象にする。短い語、候補外の表記、private modeの選択には使わない。
- Spaceによる明示変換ではライブ変換の信頼度閾値を使わず、通常の候補一覧を提示する。
- optional neural rankerを有効にしたローカルbuildでは、最初のSpaceに加え、入力が止まった後だけLIVE候補をworkerで採点する。8文字以下の短い読みは最大120 ms、9文字以上は標準180 ms待つ。毎キーの同期経路では広い候補生成もモデル推論も行わない。

期待する遷移の例:

```text
確か → 確かn → 確かな
日本 → 日本g → 日本語
ライブ変換 → ライブ変換d → ライブ変換で
変換が → 変換がt → 変換がts → 変換がつ
変換がつ → 変換が続く → 変換が続くと → 変換が続くとお
今日は → 今日はいい
そう → そうs → そうしま → そうしましょう
```

## 状態と判定

`slime-core`はライブ候補、その候補が覆う完全なかな読み、変換対象から外した安定文節を
別々に保持する。`n`、`k`、`sh`
など次のかながまだ決まらず、新しい信頼できる全文候補も作れない間は、かな読みそのものが
変わっていない直前の表記へ未確定ローマ字だけを付けて表示する。母音の入力でかなが確定した
時点では固定前の範囲を再評価する。これにより入力途中の不要なrollbackを防ぎつつ、分割境界が
変わった際に`1勝ち + がう = 1勝ちがう`のような、ラティスに存在しない表記を作らない。

全文1位と2位の差が閾値未満でも、上位経路に「直前に表示したsurface + 新しく確定した
literal suffix」と完全に一致する候補があり、そのコストが1位との差の閾値内なら採用する。
たとえば`ライブ変換`へ`で`を加えた全文1位が`ライブ変換で`なら、2位の
`ライブ返還で`が近くても読みへ戻さない。また`へんかんがつ`の1位が一時的に
`返還月`へ揺れても、`変換がつ`が競合する全文経路として同じ閾値内にあれば、直前の
`変換が`を維持する。一方、古いsurfaceを末尾へ機械的に連結することはなく、全文
ラティスが同じ表記を確認できない`1勝ちがう`は採用しない。

候補が一度1位になっただけでは固定しない。たとえば`こうい`の`行為`は、次の`う`で
`こういう`へ変わり得るため変換対象に残す。助詞を含む`変換が`が後続の`つ`を加えた
ラティスでも`変換がつ`として競合範囲内に残った場合に初めて、`へんかんが`を安定文節へ
移し、以後は`つ`以降だけを変換する。続く`続くと`も次の文字で維持された時点で同様に
安定文節へ移る。この遅延固定はアプリへの確定ではなく、Enterまでは全体がmarked textである。

助詞で閉じた境界が一度sealableになった後、次の不完全な右側入力で全文候補がその境界を
一時的にまたいだり曖昧になった場合は、境界を`pending prefix`として保持する。曖昧なstepでは
「pending prefixの表記 + 右側のliteral reading」を表示するため、安全な左文節だけが全文かなへ
戻らない。一方、この段階では全文ラティス探索を狭めない。右側4文字以上を独立変換しても
全文候補と同じ右表層になる場合だけstable prefixへ昇格する。暗黙の数字を含む表記はpending対象に
しない。句読点を含むmarked textでも、その後にsealableとなった文節は表示保護できる。ただし
新しい右suffixに句読点が入った時点では句読点fallbackへ戻し、先頭が句読点の評価窓は検索境界へ
固定しない。これにより`バスが釧路 → ばすがくしろえ`を`バスがくしろえ`へ限定するだけでなく、
`とは、政党が → とは、せいとうがは`を`とは、政党がは`へ保つ。一方、`データへ|んかん`や
`短期と|う`の誤固定は引き続き避ける。
pending表示とニューラル安全判定の論理base surfaceは別に保持し、表示保護によってworkerの
候補生成・margin判定・世代検証を変えない。

stable prefixの右側でも同じ遅延固定を繰り返す。とくに句読点後のtargetで`…や`がsealableに
なった場合、直後1〜2かなの局所表層がその境界を保つ間はnested pendingとして表示を保護し、
右側4かな以上の独立変換が一致した時点で既存stable prefixを前進させる。後続がカタカナだけなら
`ヤング`など境界をまたぐ語を優先して固定を保留する。読みと表層が一致する助詞境界に限定し、
`買わ`のような活用途中の表層はnested pendingへ昇格しない。

短い完成語が後続入力でかなへ戻った場合は、そのcomposition内で起きた実際の不安定性を記録する。
続く最大8文字の間、単一segmentの低頻度漢字語だけを再表示せず、`しゅ→種→しゅう→集荷→
しゅうかんし→週刊誌`のような連続した誤った点滅を抑える。先読みで全短語を遅延させるのではなく、
一度かな戻りが観測された後だけ有効にする。明確な複数segment変換、ユーザー辞書、Space変換、
composition確定後には影響しない。停止後の最終表記は遅延Q3 workerが同じ候補集合から回収する。

句読点後のpending対応に加え、直前表記＋literal suffixが通常10-bestの直後にある場合は、
曖昧なstepの表示保護だけ最大15経路で検証する。初回候補、確信判定、stable prefixの探索幅は
増やさない。`とうきょうこ`の11位に実在する`東京こ`を表示しても、そのprefixを検索範囲から
外さず、続く`くさい`で通常どおり`東京国際`へ更新できる。JWTD 400件では最終Core精度を維持し、
rewrite文字を`9522→9138`、rollback文字を`7337→7082`、かな戻りを
`178項目/249回→174項目/238回`へ削減した。AJIMEE 200件も最終精度を維持し、rewrite文字
`4781→4657`、rollback文字`3748→3663`、かな戻り`94項目/127回→92項目/123回`となった。
AJIMEEの数字混入stepは`181→182`だが、増分は許容正解に数字表記を含む`第2次…`を1step長く
保ったもので、新しい数字候補の導入ではない。同期処理p95はJWTD 1.66 ms、AJIMEE 2.17 msだった。
Q3の最終LIVEはUD dev/test `233/331・241/323`、JWTD `167/400`、AJIMEE `123/200`で、
4集合ともCore正解からの退行0を維持した。

`pending prefix`導入後に追加した深いラティスの表示fallbackは、全文経路を
そのまま採用するため、既存のstable prefixの右側で新たにsealableになった文節を
保護していなかった。これにより`久々の共演に → 久々のきょうえんにく`のような再発が起き得た。
fallbackがsealableな表層を壊す場合は`pending prefix + 右側literal reading`を表示し、
その状態で句読点に到達した場合も同じ表層を表示fallbackとして引き継ぐ。検索範囲は
従来どおり固定しない。同時に、表示保護で文頭だけ漢字になった長文は、workerの語尾保護を
「短い語尾だけの置換」に限定し、長文全体の修正を誤って拒否しないようにした。
導入済み公開packでの最終Q3 LIVEはUD dev/test `233/331・241/323`、JWTD `168/400`、
AJIMEE `123/200`、4集合ともCore正解からの退行0である。

停止後workerが正しい`挙げます`を1位にしても、安定接頭辞後の一拍語幹保護がapplyを拒否する
残存例があった。送り仮名が3文字以上一致する活用語に限って一拍語幹の漢字化を許可し、
`なって→成って`を生んだ2文字一致案は除外した。候補数や推論回数を増やさず、JWTDは
`168→169/400`（改善86、退行0）となった。UD dev/testとAJIMEEは不変、退行0である。

安定接頭辞を限定的に再評価する全文workerは、右targetを完全保存した接頭辞修復だけでなく、
接頭辞を完全保存した右target修復も受け入れる。両方を同時に変える候補は引き続き拒否し、右targetの
安全gateも省略しない。これにより`武道館公園で→武道館公演で`と
`電話網の中に解説さ→電話網の中に開設さ`を回収した。AJIMEEは`123→125/200`（改善61、退行0）、
JWTD `169/400`とUD dev/test `233/331・241/323`は不変、退行0である。

安定接頭辞が末尾`と`で閉じた直後に`ら`が続く場合だけ、次のカタカナ語の途中で境界を
固定しない。pending表層を保って全文候補を再検索するため、`…見据えてとらいふ…`が
`…見据えてと来ふ…`へ分断されず、`トライフォース基盤`まで到達する。通常の
`音楽とライブを楽しむ`は従来どおり分節する。この限定修正でJWTDは`169→170/400`
（改善87、退行0）となり、AJIMEEとUD dev/testは不変だった。

停止後workerの候補では、辞書変換用のliteral fallbackが最大コストのまま含まれていたため、
同期LIVEが正しいひらがなを表示してもモデルがそれを選べなかった。literalを一律に優遇すると
短い内容語の既存改善を失うため、現在のtargetがliteralで、辞書1位が一つの連続区間だけを
漢字・カタカナ化する5文字以上の読み、読み全体のカタカナ化だけを行う4文字以上の読み、または
`とか`の場合だけ、literalを辞書1位+500のコストで比較へ残す。表層を一度走査するだけで、
追加の辞書探索や推論は行わない。実モデルでは`おもろい`、`とか`、`なるんですか`、
`なんでとかになるんですか`、`とにかくめちゃくちゃになってます`をひらがなのまま保持した。
最終Q3 LIVEはJWTD `170/400`、AJIMEE `125/200`、UD dev/test `233/331・241/323`で、
改善数はそれぞれ87・61・77・88、4集合すべてCore正解からの退行0である。

ニューラル候補がmargin不足で棄却された場合も、targetが4文字以上のliteralで、ひらがな保持対象で
なければ、既に生成した辞書baseをfallbackとして適用する。短い読みへ同じ規則を使うと
`まち→街`、`せん→1000`のような曖昧語・数値化が増えるため、4文字未満は従来どおり無作用にする。
辞書再探索と追加推論は行わない。これにより`遊技台選択時の判断材料として`、
`公式ページの出典以外に知りえません`など、全文かな残りや途中崩れを回収した。
最終Q3 LIVEはJWTD `172/400`（改善89）、AJIMEE `131/200`（改善67）、UD dev `233/331`
（改善77）、UD test `243/323`（改善90）で、4集合すべて退行0である。誤答間変更も、
AJIMEEは39件中38件が正解へ近づき悪化0、JWTDの追加15件はすべて正解へ近づいた。

同期表示は全件のconfidenceを厳しくせず、10文字以内の短いカタカナ断片、単漢字差し込み、
末尾で連続する細切れ漢字pathだけを追加保護する。これにより入力途中の`とにか→トニカ`、
`とにかくめ→とにかく目`、`めちゃ→メチャ`、`めちゃく→目着`をliteralのまま保つ。
同一コードで保護marginだけを無効化したA/Bに対し、4集合のCore一致率を維持しながらrollback文字を
UD dev `99→90`、UD test `82→69`、JWTD `6984→6814`、AJIMEE `3549→3446`へ減らした。

短いカタカナ経路のうち、4かな以下で辞書entry costが5000以上の弱い語だけは、通常の未完成path
margin 1000ではなく3000を要求する。`しんせ→シンセ`のような長い語の途中にしか現れにくい表記を
遅延させる一方、低costの`マジ`、`ファン`、`ラーメン`、`テスト`は従来どおり同期表示する。
同じカタカナ表記が候補内または確定済み接頭辞にすでにある場合は、文中の固有名反復として通常marginを
使う。たとえば前半で確立した`ジョマ`を、後半の同じ読みだけひらがなへ戻さない。

4かな以上の固定可能な文節へ次の1かなを足した直後、全文1位がその文節自体を書き換えても、従来表記を
保つ通常ラティス経路がcost差1100以内なら、そのキーだけ従来表記を表示する。保護した表記は確定済み
接頭辞へ昇格させず、次のキーでは通常ラティスを再評価する。全文1位が文節をbyte-for-byte保持して右側
だけを変換する場合は保護しないため、`巧妙にえ→巧妙に得`のような右側だけの候補選択を別条件で遅らせない。
これにより`フランスは→フランス杯`のような、固定可能と判定した直後の1キー反転を抑える一方、短い
単語内部の`焼きも→焼き物`や`かいへ→改変`は従来どおり変換する。

固定可能文節の右側で、4かな以上の単一辞書語がcost 5000以下かつ次点に500以上の差を持つのに、
全文だけが曖昧な場合は、その語を`word checkpoint`としてpending文節とは別に保持する。最大3かなの
後続だけを通常ラティス内の同一表記で保護し、助詞・句読点、強い全文候補、後段ニューラル適用では
破棄する。suffix-only検索へ昇格させないため、右語を守っても左文節や以後の全文を固定しない。
これにより`変換精度もへんかん→変換精度も変換→変換精度も変換せい→変換精度も変換精度`となり、
途中の`変換→へんかん`戻りを抑える。

まだ一度も変換されていない24かな以上の長い読みで、全文1位の末尾が1かなから1文字への
変換、または1〜2かなの1文字変換に1かなliteralが続く形の場合は、末尾のみを最大4かなで
局所再評価する。局所候補にcost差500未満の
次点があれば、未完成の末尾による全文変換は表示しない。すでに変換済みの表示、stable/pending
接頭辞、局所的に完成した候補には適用しない。これにより`…担当アナウンサーがちゅうけ`で
全文が`…中家`になり、次の`い`で全文かなへ戻る往復を防ぐ。`ちゅうけいさき`まで入力されれば、
通常の全文候補で`中継先`を表示する。同様に`…あいんしゅた`を`…アイン種た`にし、
次の`い`で全文かなへ戻る表示も抑える。

まだ変換済み表示がない24かな以上の全文に、読みにない暗黙数字が初めて現れる場合も、
全文ではなく「直前文節＋数詞＋単位」の最大8かなだけを4-bestで再評価する。cost差500未満の
局所次点があれば、その数字を含む全文候補を表示しない。既に正当な数字が表示されている後続入力や
`第`に続く序数には適用しない。これにより`…たいせいよくさんかいさんか…`を
`…体制翌3回参加…`にせず、次キーで全文かなへ戻る往復を防ぐ。

長い未確定複合語で全文1位と次点の差が500未満でも、直前表示が1位と8文字以上一致し、
次点より4文字以上長く一致する場合は、最大4文字の末尾変更だけを表示専用の
`continuity checkpoint`として保持する。新しく変えるsegmentは単独でも辞書1位かつ次点差
1000以上でなければならず、暗黙数字と1〜2文字だけ増えるカタカナ候補は除外する。
checkpointはstable文節へ昇格せず、後続のliteral延長だけは一致差2まで許可する。
これにより`全国高等学校野球選手家→全文かな`や`…選手権→…選手喧嘩`を避け、
`全国高等学校野球選手権かな→…神奈川たいか→…神奈川大会（リポーター`と連続表示する。
一方、局所差565の`じんこ→神子`や短い`もひ→モヒ`は採用しない。

安定接頭辞は辞書語の途中に置かない。特にliteral語`もの`を`も｜の`で分割すると、右側の
`のまで`が独立変換されて`の間で`となり、その誤りが次の安定接頭辞へ昇格する。全文辞書1位に
`もの/もの`のsegmentが境界をまたいで現れた時点でsoft checkpointへ再オープンし、
`マニアックなものまで`や`ダークな物語`を全文脈のまま評価する。

非同期LIVEの品質はコードだけでなくbundle内モデルにも依存する。開発用macOS bundleには
評価済みの`zenz-v3.2-small Q3_K_M requant`を使う。旧`zenz-v3.1-xsmall Q5`へ差し替えると、
同音異義語の正解数が4集合すべてで下がり、Core正解からの退行も再発するため使用しない。

並列助詞`や`も文節境界として次の未完成語から分離する。これにより
`週刊少年サンデーや|しゅ…`で左側全体をかなへ戻さない。ただし`や`は`ヤング`や`闇`の語頭にもなるため、
直後1かなでは安定接頭辞への昇格を保留する。上位4経路の同一segmentが境界をまたぎ、カタカナを含む
表層になる場合はその完全な辞書経路へ再オープンする。追加探索はこの保留中の`や`境界だけで、通常キー
入力には入らない。`習慣や|ングジャンプ`を固定せず、後続入力で`週刊ヤングジャンプ`へ修復できる。

句読点で閉じた表示は検索範囲を固定しないsoft checkpointとして保持する。後続の確信候補が
句読点左を訂正した場合は、その全文pathのsegment境界から訂正後の表層を回収してcheckpointを更新し、
破棄しない。次の入力が曖昧なら、直前の表示へ新しいかなだけを足す。したがって
`…に始まり、人口の…長い子`の次に`み`を入力しても文全体や読点右がかなへ戻らず、後続の確信候補は
引き続き全文を訂正できる。すでにstable prefixがある右target内の句読点にも同じ規則を適用する。
暗黙数字を含む直前表示は延長せず、読みへ存在しない数字を曖昧なstepへ持ち越さない。
中点`・`も同じsoft checkpoint境界として扱い、`新日本製鐵・すみ`の入力中に完成済みの左側を
`心にほんせいてつ・すみ`へ戻さない。中点以降の検索範囲は固定せず、確信候補による訂正は許可する。
開き括弧・開き引用符も新しい入力領域の境界として扱う。`…という「とうきょ`の入力中は
`…という「`より左を保持するが、引用内を含む後続の全文検索と訂正は引き続き許可する。

読みへ存在しない数字は、入力全体が数だけ、単独の`第2`、または直後に数助詞・単位がある場合だけ
同期表示する。`位置→1`、`について→2つ`、`新日本→新2歩`のような未完成語の誤分割は拒否し、
直前の変換済み表示へ新しいかなだけを足すsoft checkpointへ移す。直前に保護した文節と競合しても、
右側が2かな以下なら保護文節を残して入力を待ち、3かな以上で競合が続く場合だけ古い境界を破棄する。
句読点に到達した場合は保護表層と句読点までを新しいcheckpointにする。`個・度・時・期`は同音語が多いため、
上位10経路の数字なし候補に2000 cost以上勝つ場合だけ許可する。日付・人数・順位などの明確な単位は
従来どおりで、入力に数字が明示されている場合とSpace変換にはこの制約を適用しない。

停止後workerの長文候補がすべて同じ暗黙数字分割に偏り、cost差1000以内に非数字候補が
ない場合は、最良pathの文節境界内だけを探索する。先頭候補と候補数は変えず、数字を含む
末尾候補を最大6件だけ非数字候補へ置き換える。これにより`均一な8日銀の膜を形成`を
`均一なヨウ化銀の膜を形成`へ修復する。すでに近い`点対称の位置`があるなど、modelが選べる
非数字候補が元からあるときは候補集合を変えない。差し込んだ候補の辞書priorだけは1位+250を
上限にし、暗黙数字pathのcost差だけでモデル比較が無効にならないようにする。

確定可能で、短いexact語として崩れやすい印がなく、数字も含まない文節が次の1かなで候補を
失った場合は、その1stepだけ「直前表層 + 新しいかな」を表示する。次のかなでは通常の全文探索へ戻し、
この表示を同期探索の保護条件として連鎖させない。停止後workerの候補生成・安全判定も、表示中の
checkpointではなく未解決readingをbaseにする。これにより表示だけを安定させながら、Q3が以前
回収していた全文候補を失わない。

確定印がまだない長い表層でも、読みが4かな以上あり、直前表示が漢字またはカタカナで終わり、
次の1かなに対する辞書1位が直前表層をbyte-for-byteで継続する場合は、直前表層を未確定checkpoint
として保持する。新しいかな自体は変換せず、曖昧さが解けるまで右側だけをliteral表示する。これにより
`遊技台選択→ゆうぎだいせんたくじ…`の全文かな戻りを`遊技台選択じ…`へ抑える。ひらがなで終わる
活用途中、数字を含む表層、現在の辞書1位が直前表層を書き換える場合は対象外である。

辞書1位が直前表層を書き換える場合も、現在の読みが12文字以内なら4-bestだけを確認する。1位から
500 cost以内に直前表層を継続する経路があり、直前の読みが句読点を除いて4かな以上なら、表示専用の
`close continuity checkpoint`として1かなだけ保持する。例えば`ないかくし`は、1位`ない隠し`に
対する僅差の`内閣し`を根拠に`内閣し`と表示する。この状態は全文worker rankingを作らず、次の入力で
通常探索へ戻す。句読点を文字数に含めた試作は`、ふぇい`の3かなでも早期発火し、最終的に
`かつ→且`を1件発生させたため棄却した。

停止後モデルが、辞書baseより3000 cost以上悪い候補へ末尾2文字以内だけを書き換える場合は、
モデル確信度にかかわらず適用を拒否する。これにより`東方向に伸び→東方向に野火`のような
短い末尾の暴走を止める。3000 cost未満の通常候補帯と辞書baseは引き続きモデルが選択できる。

停止後workerは、表示済みのひらがな4文字以上を同じ読みのカタカナへ変えるだけの候補も適用しない。
同期表示が保護した`…おもろい…`を文脈付き候補が`…オモロイ…`へ戻す経路を閉じるためである。
短い`マジ・ユリ`と、カタカナ語を列挙する読点後の末尾修復は対象外にして、正当な外来語表記を保つ。

モデルがliteral targetを棄却した後も、辞書baseが2字以上の漢字だけからなる語幹を導入し、末尾3かな
以上をそのまま保持する場合はbaseへ戻せる。`せいさくしている→制作している`のような活用語を回収する
一方、1字だけに圧縮する`うかがえる→伺える`と、変換語幹の前にひらがなが残る口語句全体は対象外にする。
これにより`おもろい`・`なるんですか`・`とにかくめちゃくちゃになってます`のliteral保護を迂回しない。

カタカナ語の列挙で最後の4かなだけが未解決の場合は、直前が3文字以上のカタカナ語と読点で、候補が
末尾だけを全カタカナ化する場合に限って短いliteral保護を解除する。これにより
`ファンタ、げろっぱ→ファンタ、ゲロッパ`を許可する一方、`とか`や通常のひらがな語は保護する。

助詞らしい1かなを含む長いカタカナ固有名も、誤ったpending境界へ固定しない。助詞直前の連続表層が
漢字とカタカナの混在で、上位4経路の単一カタカナsegmentが境界より2かな以上前から右へまたぐ場合だけ、
そのpendingを解除して完成語をsoft checkpointへ置き換える。これにより`マンネルへ|いむ`を
`マンネルヘイム`として保持し、次の`じ`で`万ネルへいむじ`へ戻さない。カタカナsegmentが助詞位置から
始まる`グループに|わか…`、`米国は|んど…`は対象外で、通常の分節を維持する。

同じ誤境界がすでにstable prefixへ昇格していても、右6かな以内の全文第1候補に境界をまたぐ連続
カタカナrunがあれば、その境界だけを再オープンする。連続runは複数segmentでもよく、助詞より前に
3かな以上ある`ヴォルで|モート`・`フェアと|レード`、または右側が独立文節を開始できない`ー`で始まる
`は|ード`・`も|ール`を対象にする。`が|んだむ`は`が`境界だけを対象とし、全文第1候補がカタカナ語を
裏付ける場合に限る。追加経路は第1候補だけを見るため、既存の上位4件探索を通常入力へ広げない。

ひらがな機能表現も、stable境界をまたぐ全文第1候補の単一segmentが読みと表層を同じ`できる`または
`という`として保持する場合は再オープンする。これにより`利用で|きる→利用で切る`と
`だけと|いう→だけと言う`を防ぐ。`包丁で|切る`や引用後の`と|言う`は第1候補のsegment表層が一致せず、
通常どおり助詞境界を維持する。追加辞書探索はこの2パターンが完成した時の第1候補だけである。

stable prefixの右側をBOS扱いで独立変換した結果が、2かな以上のliteralに続いて2かな以下の単漢字nodeを
置くか、1かなliteralに続いて3かな以上からなる2字以上の漢字nodeを置く断片形なら、全文ラティスで
接続costを復元する。全文経路が既存stable readingのsegment境界と一致し、その左表層をbyte-for-byte
維持する場合だけ右targetを置き換える。これにより
`供養塔を|あら下無に`を`供養塔を|荒らしたなに`へ戻し、後続の`何者か`まで誤表層をstableへ移さない。
同じ条件で`繁殖期は|や成果では`も`繁殖期は|野生下では`へ戻す。
断片形でない通常のsuffixには全文探索を追加せず、stable prefixそのものも変更しない。

全文第1候補の変換済み単一segmentが、助詞らしいstable境界より前3かな以上・後2かな以上をまたぐ場合は、
その長い辞書表現をsoft checkpointへ戻す。右suffixは6かな以内、stable末尾と読みの助詞表層が同一、
segment表層に漢字2字以上とひらがなの両方があることを必須にする。これにより
`制裁を|書いた`として固めず、全文segmentの`精彩を欠いた`を維持する。通常の短い助詞＋動詞は
segmentが境界をまたがないため対象外である。

曖昧な`とる`だけは、literalの先頭`と`をstableへ昇格しない。全文第1候補が既存stable左側を正確に保持し、
右側を「漢字1字＋送りかな`る`」にする場合、その全文表層をsoft checkpointへ置く。suffix単独第1候補を
固定しないため、左文脈に応じて`態度を取る`・`写真を撮る`を区別でき、停止後workerも全文を採点できる。
他の2かな活用語へ一般化するとかな戻りが増えたため対象にしない。

全文scopeでstable prefixをbyte-for-byte保持したまま、末尾literal 2かなを`会い`のような
「漢字1字＋同じ送りかな1字」へ変えるcandidate moveも許可する。ただし辞書baseそのものではなく、
Q3が文脈で別候補を1位へ動かした場合だけに限定する。これにより`あい→会い`を回収しながら、辞書1位の
古い表記`おけ→於け`を自動適用しない。3かな以上、文字数変更、stable prefix変更は対象外である。

この保護後、変換済み接頭辞の末尾に残った1〜4かなを、辞書1位が接頭辞を完全保持したまま
2字以上の漢字語へ直せる場合は、モデルmargin不足で棄却されても辞書baseを適用する。
`荼毘に付されたいたい→荼毘に付された遺体`を回収し、最終Q3 LIVEはJWTD `174/400`
（改善91）、AJIMEE `131/200`（改善67）、UD dev `234/331`（改善78）、UD test `246/323`
（改善93）、4集合すべてCore正解からの退行0となった。

安定接頭辞の最大2漢字修復は、右targetをbyte-for-byte保持する場合に加え、現在literalのtargetを
辞書候補として同時に変換できる場合にも全文workerへ渡す。たとえば`拡散版`を`拡散板`へ直しながら、
右側の`かくさんしてちょくせつしょうしゃ`も一度に変換できる。全文modelがmargin不足なら、
同じworker内で従来のsuffix-only requestへ一度だけ戻し、安定接頭辞修復を諦めても右側変換は失わない。
評価器はこの経路を`suffix_scope_retries`として集計する。最終AJIMEEは`132/200`（改善68）、
JWTD/UD dev/UD testは`174/400`、`234/331`、`246/323`を維持し、退行は4集合とも0だった。

1かなは同期表示では引き続き変換しない。停止後workerに限り、安定接頭辞または外部左文脈がある場合だけ
候補を生成し、literalひらがなも辞書1位+500で残して通常marginを要求する。これにより
`大正+き→期`、`精神+か→科`、`航空+き→機`、`正教+と→徒`を回収しつつ、
`ラーメン+は`、`東京+に`、`本+を`、`これ+が`はひらがなのまま維持する。曖昧な`東京+と`も
margin不足で無作用になる。最終Q3 LIVEはUD dev `259/331`、UD test `262/323`、AJIMEE
`133/200`、JWTD `174/400`で、4集合すべてCore正解からの退行0だった。

辞書候補は通常2経路だけ探索する。上位2経路が同じ表記なら、内部の分割差を
ユーザーに見える曖昧さと誤認しないよう4経路まで適応的に広げ、異なる表記同士を比較する。
第一候補と次の異なる表記のコスト差が500未満なら、上記の安定した拡張を除いて新しい全文候補は採用しない。安定候補の確認には同じ探索で取得済みの経路を使い、追加探索は行わない。
閾値を一律に525へ上げるとUD devのrollbackは`64 → 59`回へ減るが最終一致率が
`0.4713 → 0.4683`へ低下し、600ではrollback `48`回と引き換えに一致率`0.4411`まで
低下した。安定性だけを根拠に全候補の閾値を広げず、500を維持する。

ユーザー辞書の完全一致は常に優先する。通常の入力履歴は、旧バージョンで暗黙確定された
誤変換を再表示する可能性があるためライブ変換へ無条件には使用しない。ライブ変換で使うのは、
同じengine内で候補移動・番号・clickにより明示的に選んだ直近64フレーズ、または永続履歴で
2回以上選んだフレーズのうち、上記の長さ・候補順位・コスト差をすべて満たす表記だけである。
session内の一時選択はcaretやdocument contextの切り替えでは消さないが、user data再読込とengine破棄で
消える。永続履歴の1回だけの選択は次のengineへ持ち越さず、private modeでは一時・永続とも記録しない。
この明示的な選択は、同じ完全表記が辞書1位でも僅差で読みへ戻っていた場合の曖昧さも解消する。
短い語や曖昧な入力の履歴はSpace後の変換候補と補完候補の順位付けにだけ使用する。

署名済みまたはローカルに導入した辞書packの左文脈ルールもLIVEで利用する。現在の未確定読みと
直前の確定表記（安定文節がある場合はその表記も含む）が完全一致し、規則の表記が通常N-best
10件と第一候補から2500 cost以内に残る場合だけ採用する。優先順位はユーザー辞書、明示的な
フレーズ履歴、pack文脈、ニューラルの順で、private modeではpack文脈も使わない。文脈規則が
採用された読みは非同期ニューラル再順位付けの対象外にし、決定的な軽量規則を後着taskが
上書きしない。Space後の明示変換では同じpack規則を候補内の整合した隣接文節にも使うが、
毎prefixへ適用すると長文のrollbackが増えるため、LIVEは読み全体が一致する規則だけを使う。

## 既知の限界

現在の軽量rankerは、単語・品詞接続コストに加えて、文書内の表記反復や限定された
定型接続を使うが、文の意味までは理解しない。そのため初見の`制度/精度`、`漢字/感じ`、
`箸/橋`のような同音異義語を、信頼度閾値だけで正しく選ぶことはできない。

ニューラル候補の1位が2位より十分優勢な場合だけ自動採用する。モデル1位が辞書1位と同じ場合も
margin判定を省略しない。省略すると、同期coreが曖昧として残したかなを、確信差のない辞書1位へ
置換できるためである。xsmall Q5ではmargin 0.5、
smallの精度優先profileでは短い読み`lambda=0.2`、4文字以上`lambda=0.6`を使い、switch marginは
それぞれ0.2と0.3に分ける。同じ字数で先頭または末尾を共有する人名表記候補群だけは`lambda=0.5`へcapする。
辞書baseより1300 cost以上深く、3字以上の漢字列の内部1字だけを書き換える候補も拒否する。
この制約は`遊技台→遊戯台`のような深い複合語内置換に限定し、語頭・語尾の置換は妨げない。
10文字未満のtargetと安定接頭辞を再オープンするtaskでは、辞書1位と文字数が異なる候補への
自動変更を拒否する。10文字以上では、モデル1位が辞書baseより0.5以上優勢な場合だけ許可する。
長い変換済み表記の末尾に残った
4文字以下のliteralかなだけを漢字化する変更も原則拒否する。例外は、末尾全体が読みより長くない
2字以上の漢字語になり、通常のニューラルmarginも通る場合だけである。これにより
`とっけん→特権`や`いっしん→一新`を許可しながら、`である→で有る`、`する→刷る`、
`かつ→勝`のような機能表現・単漢字の過変換を抑える。さらに、同期LIVEがすでに表示した
漢字語幹+かな活用語尾を、語尾ごと別表記へ置換する変更を拒否する。これにより文脈上正しい
`通う`を`火曜`へ変える退行を防ぐ。一方、末尾のかな活用を維持し、その直前だけを漢字化する
`しぼうし→死亡し`、`やぶれ→敗れ`、`強くひかれる→強く惹かれる`は許可する。単独の
格助詞・係助詞は活用語尾に含めず、`ともに→共に`や`もとに→下に`は自動変更しない。
公開language pack込みの実非同期task評価では、UD dev 75件、未使用test 86件、JWTD 68件、
AJIMEE 50件をCoreから改善し、top-1退行0だった。

安定接頭辞の直後に促音`っ`が現れた場合は、直前の助詞らしい境界を解除してmarked text全体を
再評価する。促音は独立文節の先頭にならないためで、`不逮捕と|っけん`、
`混成が|っしょう`、`専門が|っこう`という早すぎる固定を防ぐ。AJIMEEでは同期Coreを
`0.305→0.320`、最終LIVEを`0.555→0.570`へ改善し、他の3集合を含めて退行0だった。

3文字以上の未解決かな末尾については、辞書1位とモデル1位が一致し、確信差0.2以上の場合だけ
辞書1位の適用を許可する。別候補へのoverrideは通常margin 0.2を要求し、かな入力へ暗黙の数字を
導入する候補と2文字以下の単漢字化は対象外にする。これによりAJIMEE最終LIVEは`0.575`、
改善51件となり、UD dev/testとJWTDを含めて退行0を維持した。

モデル1位が文字数gateで棄却された場合も、読みと辞書1位が同じ文字数で、先頭1かなだけを漢字へ
置換し、末尾2かな以上をそのまま送り仮名として保持する辞書1位ならfallbackできる。これにより
`是非かける`を`是非書ける`へ直す一方、圧縮表記の`うかがえる→伺える`、短い`いたら→至ら`、
全カタカナの`おもろい→オモロイ`は対象にしない。

単純な主題`は`までの表記が辞書1位と次点で異なる場合は、表示confidence 500を維持したまま、
安定接頭辞へ移すmarginだけ1000へ上げ、最大32文字の右文脈を待つ。候補差が主題より後ろだけに
ある場合、32文字を超える長文、`少年院に|は`のように接頭辞をまたぐ`には`は通常閾値へ戻す。
これにより`この競争はハンデキャップで→この競走は…`と`イスラエルの感染は→艦船は`を回収し、
AJIMEEは`0.580`、改善52件となった。後述のworker限定15-best、通常margin 0.2、長いtargetの
限定cost-gap緩和込みでJWTDは`0.3900`、改善73件となる。UD dev/testを含む4集合で
従来正解からの新規誤りとCore正解からの退行は0だった。
同期実行では候補生成と採点のp95が長文で最大119 msだったため、
入力中のengineを参照しない不変snapshotと独立したworker taskへ分離した。macOSは安価なtask
snapshotをキー処理直後に作り、8文字以下では最大120 ms、9文字以上では180 msのdebounce後に
workerを開始する。small Q3の30回再測定でsnapshot取得p95は0.005 msであり、候補生成とモデル推論は待機後まで行わない。
worker開始前と完了後に入力世代、読み、文脈、marked text、選択範囲と
marked range、候補集合を再検証する。1つでも変わっていれば結果は無作用で、private modeではtask自体を作らない。
worker内の候補は読み8文字以下で10件、9文字以上で15件に固定する。16件で得たJWTDの
追加3件を15件でも維持し、AJIMEEはさらに1件改善した。UD dev/testを含めて既存正解の
損失は0である。同一条件の単独process再測定では、15件のworker p95はJWTDで
`80.23/81.40 ms`、AJIMEEで`112.95 ms`、16件はそれぞれ`87.72/132.80 ms`だった。
12件と14件はJWTDの改善を1件失い、32件はJWTDをさらに1件改善した一方p95
`325.25 ms`となったため使わない。最初のSpace、
毎キーの同期LIVE、安定表示を後続入力で維持する通常ラティスは従来どおり10件である。
採用した表記は、後続入力でも同じ表記が通常ラティスの上位10経路、コスト差2500以内に残る間だけ維持する。
明示Spaceの同期rankerと、訂正を同じsessionの次回LIVEへ反映する一時履歴も引き続き使用する。

通常のcost-gap上限1000も維持する。ただしworkerの変換targetが10文字以上の場合だけ上限を
1500まで緩和する。JWTDで候補内にあった`早期に勾留するために`と`旧制宮城県佐沼中学校`を
追加回収し、UD dev/test・AJIMEEを含めて退行0だった。無制限採点は`最近では映画→栄華`を
生じたため使わない。同期Spaceは1000のままで、追加推論は180 ms停止後のworkerに限る。

安定接頭辞がある場合、候補生成とモデル入力は右側の未確定suffixだけへ絞り、接頭辞表記を
左文脈として渡す。一方、短い読み用`lambda=0.2`と長い読み用`0.6`の選択はmarked text全体の
読み長で行う。suffixだけで判定すると`てんたいしょうの|いち`が短い語扱いになり、モデルが
文脈上の`位置`を強く支持しても`点対称の1`が残っていた。全体長で長文weightを選ぶことで、同じ
通常N-best候補から`点対称の位置`へ修復する。cost-gapと数字入力保護は変更しない。

安定接頭辞内に単純主題`は`までの近い別表記が残り、右suffixが4文字以下の場合だけ、停止後の
workerは接頭辞を4-pathで検査してmarked text全体を再順位付けする。毎キーの同期表示、通常の
安定接頭辞、Space候補は変更しない。これにより`機構は…評点を超えることは|なく`を、停止後に
`気候は…氷点を超えることはなく`へ修復した。全文を無条件に再評価する案はJWTDを`157→152`、
長いsuffixがある場合も再評価する案はAJIMEEを`117→115`へ悪化させたため採用しない。最終条件は
JWTDを`157→158/400`（改善75、退行0）へ上げ、AJIMEE `117/200`、UD dev `233/331`、
UD test `241/323`を維持した。

主題に限らない安定接頭辞の誤りは、明示Spaceの全文候補に正解があってもsuffix-only workerからは
修復できない。そこで全文候補15件の中に、現在の右suffixをbyte-for-byte維持し、安定接頭辞だけを
同じ文字数のまま最大2文字変更する候補が実在する場合に限り、停止後workerへ全文を渡す。適用時にも
同じ条件を再検証するため、モデルは右suffixを別表記へ交換できない。これにより
`ラーメンには自身があるが→ラーメンには自信があるが`のような早期固定を修復した。
長文weight `0.5`のまま、JWTDは`163/400`（改善80）、AJIMEEは`121/200`（改善57）となり、
UD dev/testは`233/331`・`241/323`を維持した。4集合ともCore正解からの退行0である。単独processの
worker p95はJWTD `98.58 ms`、AJIMEE `124.76 ms`で180 ms debounce内だった。

全文・長い未解決targetでも文字数を常に固定すると、十分な文脈があっても`ないか→内科`のような
通常のかな漢字変換をworkerが捨てる。そこで10文字以上、安定接頭辞の再オープンではない、
辞書baseに対するモデル優位差0.5以上のときだけ文字数変更を許可する。短い助詞・活用語尾の保護、
通常margin 0.2、暗黙数字化の拒否、世代検証は変更しない。これにより
`内科・アレルギー科…皮膚科`と`塩素で髪が茶色くボサボサに傷んでしまい`を回収した。
JWTDは`167/400`（改善84）、AJIMEEは`123/200`（改善59）となり、UD dev/testは
`233/331`・`241/323`、4集合ともCore正解からの退行0を維持した。単独processのworker p95は
JWTD `103.52 ms`、AJIMEE `129.14 ms`で180 ms debounce内である。

公開corpusで複数回確認でき、現在の辞書に対して実際に誤順位を直す複合語は、可逆な辞書packで
LIVEへ反映できる。`henkanseido`は12-entry local packでの検証後、Public Domainの根拠を
確認できる1 entryだけを本体の補助layerへ昇格した。辞書packも履歴もない空のdata
directoryで、最終キー直後とSpace後の双方が`変換精度`になる。既存packの同一entryを優先し、
明示的なcost overrideは残すため、更新後も既存ユーザーの候補pathを不要に変えない。

かな入力から辞書1位にだけ数字が現れ、ニューラルwinnerが非数字の場合は、通常のswitch margin
0.2ではなく0.1を使い、文字数変更を許可する。1位–2位の確信差にも同じ0.1を要求する。
これにより`いちこてい→1固定`を`位置固定`へ直す。
明示的な数字入力と、`1日`のようにwinnerにも数字が残る表記はこの緩和対象にしない。UD/JWTD/
AJIMEEの計931件では改善を4件増やし、正解からの退行は0だった。

Coreの同期LIVEでは、かな由来の数字segmentが直後のカタカナ語へ連結される場合を自動表示しない。
`にうぃきぺでぃあ→2ウィキペディア`、`さんふぁん→3ファン`のような数字は、一度出ると
後続のliteral extensionに残り続けるためである。数詞単独、`第2`、`2月`、`1日`、`1位`などの
序数・日付・数詞単位、およびユーザーが直接入力した`２ファン`は従来どおり許可する。
判定は変換segmentの構造と一般的な数詞単位だけを使い、語別表記や候補外文字列を生成しない。

停止後rankerが短い読みを確信差不足で棄却した場合でも、左文脈付きの生成済み辞書baseがあれば、
1〜3かなの未確定targetだけは適用できる。stable prefixの再オープン、暗黙数字、読み全体のカタカナ、
`とか`、および読み末尾と同じ終止形送り仮名を持つ候補は除外する。このため`東京`に続く`と→都`や
名詞の`たく→宅`は回収するが、`つく→付く`、`なる→鳴る`、`とか→トカ`はrankerの棄却を尊重する。

短語の文脈付き辞書baseがcost-gap gateを越えてモデル採点を省略する場合も、同じ安全条件を通して
適用する。単にcost-gap上限を広げると推論量だけが増えたため、上限1000は変更しない。また外部文脈が
あり、文脈付き辞書1位が3〜4かなの2漢字語で、同期表示が「漢字1字＋助詞らしい1かな」の場合は、
`朝の→浅野`のような語彙化を許可する。stable prefix内、辞書1位以外、2漢字以外には広げない。

固定前の範囲では、かなが確定した後に候補が曖昧なら変換済み表記が読みに戻る場合がある。
現在の遅延固定は安全側として助詞で閉じた文節を対象とし、動詞・形容詞だけで閉じる文節の
固定はまだ行わない。
将来の文脈rankerでも、精度だけでなく次を評価する。

- 変換済み接頭辞のrollback回数
- 同じ範囲での表記の往復回数
- ライブ候補を訂正するためのSpace、候補移動、Backspaceの回数
- 暗黙確定が履歴へ与える影響
- 10、50、100文字での1キー平均とp95 latency

`slime-live-transition-evaluate`は、このうちrollback、かな戻り、数字混入と同期core latencyを
AJIMEE形式の公開データで再現可能に測る。初回計測では、長文で句読点より左まで再探索される
巻き戻しが多いことも確認した。句読点で検索範囲を即固定する試作は、読点直前の誤変換を固定して
最終精度を落としたため採用していない。代わりに、句読点で閉じた表記を曖昧な瞬間の表示用
fallbackとしてだけ保持する。毎キーの全文探索は継続し、信頼できる候補が得られれば左側も
置き換える。AJIMEE 200件では最終LIVE一致率`0.305`を維持し、rollback文字数を
`4660 → 4588`、かな戻りを`231 → 217`へ減らした。

さらに、曖昧な上位2経路が同じ読み境界と変換済み接頭辞を共有する場合は、全文かなへ戻す前に
「共有接頭辞 + 未変換末尾」と完全一致する通常10-best経路を探す。直前の信頼済み表示より
共通接頭辞が長くなり、1位とのcost差が2500以内で、新しい数字を導入しない場合だけ表示する。
このfallbackも`reliable=false`で文節固定せず、候補外表記や前回表示との機械的なhybridを作らない。
UD dev/testは全指標不変、JWTD devは最終一致率`0.205`を維持してrollback文字を
`9602 → 7282`、かな戻りを`487 → 358`、rewrite文字を`14400 → 10700`へ減らした。
AJIMEE 200件も最終一致率`0.305`を維持し、rollback文字`4586 → 3805`、かな戻り
`216 → 167`、rewrite文字`6530 → 5227`となった。同期p95はJWTD `0.73 → 1.07 ms`、
AJIMEE `1.27 → 1.64 ms`である。
