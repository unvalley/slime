# LIVE変換の残存失敗と境界待機の比較

2026-09-12、二語の前半修復を採用した版から再分類した。かな2,745件中、完全一致しないものは1,054件。正答が観測したLIVE候補内にある609件、Space候補だけにある94件、両方の観測候補にない351件に分かれる。有限の候補一覧による分類であり、辞書に語彙が存在しないという証明ではない。原文表記との差や元の読みの問題も含む。

LIVE候補内の609件は、モデルが別候補を一位にした504件、順位結果なし83件、正答を一位にしたが適用されなかった22件。83件はworker status 6であり、モデルの順位誤りと断定しない。

Space候補だけに正答がある94件のうち25件は、Spaceで実際に正答する。この25件を次の診断対象とした。「特典をも受け」「可能な限りは位してあり」「が以降的かつ不安定な性格」では、それぞれ「も」「は」「が」が固定されたため、worker対象が「うけ」「いしてあり」「いこうてき…」になっていた。辞書に正答がない問題ではない。

トレースの初回はカタカナを直接Coreへ渡したため、評価器の入力経路と異なり変換が起きなかった。誤った初回トレースは `.raw-katakana.txt` として残し、評価器に合わせてひらがなへ正規化したトレースを取り直した。解析には後者だけを用いた。

## 共通の一文字待機の実験

助詞に見える末尾の直後を一文字待つ条件を比較した。製品には未採用で、ソースは採用済み版へ復元した。QAアプリも変更していない。辞書・モデルは同じで、語ごとの例外は追加していない。

選んだ25件は0→15と改善したが、正常例を含むローマ字200件は108→113、8改善・3退行となった。「そのま→その真」「誓い→誓」などを新たに生じるため、単純に全助詞を待つルールは採用できない。Coreは235成功・17失敗。内部の固定範囲が変わっただけの失敗もある一方、「絵を書き、衣服を→得をかき、いふくを」など実際の表示退行も含む。失敗したテストを一律に書き換えて受け入れない。

広い全件比較は凍結した実験バイナリで完了した。かな2,745件は1,691→1,712だが、42改善・21退行で、不正解同士の変更も79件ある。正解数の純増だけでは採用せず、共通待機ルールは不採用とした。全件の最終結果は `target/evaluation/live-particle-lookahead-20260912/full-comparison.json` と `decision.json` を参照。最新の分類・入力ファイル・再現スクリプト・元結果ハッシュは `target/evaluation/live-failure-triage-20260912/` に保存した。

## 一文字だけ境界を戻す診断

評価器の不一致行に `live_request_left_context` を追加した。workerが実際に使った文脈を記録し、固定部分を文字数から推測しない。既存25件を再実行し、追加したフィールドと時間計測を除く全結果が変更前と同一であることを検証した。製品の変換処理やC ABIは変更していない。

上記25件のうち、固定部分の最後が助詞文字で、それ以外の前半が正答と一致する9件を抽出した。最後の一文字を末尾の読みに戻し、それより前を外部文脈として与える別入力を作った。LIVE5/9、明示変換4/9。設け、廃してあり、外向的などが回復する。一方、にしよう、の緒が切れると、長野大和守、ではなはLIVEで未解決。

これは再構成した入力を使う探索上の診断であり、元の全文を入力した製品の改善件数ではない。短くした読みに伴いランキング設定やCoreの入力履歴も変わるため、元のworker範囲をそのまま差し替えた比較とも異なる。次に検証する場合は、元のスナップショットの世代・前半・文脈を保持し、適用時に一文字の再開範囲だけを変更できるようにする必要がある。ユーザー辞書・履歴由来の保護対象を再開しないことも必要。

診断入力と結果は `one-character-reopen-items.json` / `one-character-reopen-result.json`、ハッシュと既存結果一致は `diagnostic-manifest.json`。共通待機実験は不採用のままで、採用版はかな1691/2745の二語修復版を保持する。
