# Long/contextual LIVE cost-gate experiment — 2026-09-12

An isolated evaluator changes only LIVE_LONG_TARGET_MAX_COST_GAP from1500 to2000. Eligibility is unchanged: a target reading of at least10 characters, or at least6 with nonempty left context. The original global1000 gate, explicit1500 gate, scoring weights, confidence margins, surface guards and generation-safe application remain unchanged. This is separate from the existing Core stable-prefix repair threshold2000.

The motivation is the preceding worker trace:49 unranked failures did not enter LIVE model scoring because of the cost gate. A broad5000 diagnostic recovered eight of those failures but had no correct controls. The present experiment compares all4945 rows against the adopted literal-preserving Space agreement reports, including previously correct inputs. It is a gate experiment rather than a general change to global scoring parameters.

The candidate was compiled and frozen; the FFI source was restored byte-for-byte to the adopted1500 version, and the normal release evaluator/library rebuilt. The normal app retains1500; any later2000 app mentioned below is an isolated, unadopted QA build. Candidate-specific unit-test expectation updates, latency assessment and native replay would be needed before adopting this policy; the isolated measurement binary is not adoption evidence by itself.

The complete 4,945-row comparison shows eight exact-match LIVE gains, three losses and five other changes; every Space output is unchanged. The losses include the semantic regression 作詞 → 策士, the spelling difference 興味津々 → 興味津津, and 化している → かしている. These are distinct kinds of error, not three equally severe semantic regressions. The unqualified gate relaxation is not adopted.

A second isolated variant applies a 0.5 score-margin floor only to ordinary LIVE requests admitted beyond the previous relaxed gate (and beyond any larger caller-configured gate). Reopened boundaries and confirm-base-only requests retain their existing policy. It yields seven exact-match gains, one loss and four other changes over the same 4,945 rows, with all Space outputs unchanged. The remaining loss is 化している → かしている: model likelihood prefers the existing kanji display, but dictionary weighting still chooses the kana base with a combined margin above 0.5. Trace details and all changed inputs are retained with the experiment artifacts.

A third isolated variant preserves the finite-cost displayed candidate when the same model scores prefer it to the proposed winner, limited to that newly admitted scope. It reuses existing scores and does not change the separate unresolved-literal width-fallback index. The 16-input probe initially appeared to avoid the losses, but that inference used the wrong comparison baseline: no change relative to the raw Core display does not imply preservation of the adopted worker result. The completed 4,945-row comparison still has seven gains, one loss and four other changes; 化している → かしている remains. This small diagnostic is selected from changed cases, so it is not evidence of regression safety on its own. Neither variant is adopted into the app.

The before/after trace for 609450 identifies a control-flow regression. At 1500, the full request (base gap 1531) returns no ranking, then the suffix かしている is scored and repaired to 化している. At 2000, the full request returns a successful unchanged ranking, which suppresses that existing suffix retry. The model-preferred-current helper addresses neither the missing retry nor this baseline behavior and is removed from the next proposal.

For the シート case, the full current display is already correct. The target model scores and dictionary cost both favor 本革シート, but later literal-tail postprocessing selects 本革シーと. Therefore a guard inside raw score ranking runs too early. The katakana-only variant still regresses this row and is rejected without a full rerun.

The next proposal (live-gap2000-suffix-20260912) checks newly admitted ordinary results after all existing postprocessing and dictionary fallback. The old model-current score preference and extra policy field are removed. All earlier gate variants remain unadopted. The 19-row diagnostic now compares directly against the adopted worker outputs, rather than treating raw Core unchanged status as a successful result.
