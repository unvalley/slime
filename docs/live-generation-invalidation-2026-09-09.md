# LIVE推論の古い結果が再入力へ適用される問題の修正（2026-09-09）

キャンセルして同じ読みを入力し直したとき、以前の入力で作ったLIVE推論結果が新しい入力へ適用される問題を修正した。

修正前は読み・表示・前文脈などの状態が一致すれば結果を適用できた。そのため、一度状態を変えた後に同じ状態へ戻る操作を区別できなかった。Q4同梱のSwiftプローブでは、「きょうたい」で取得した推論をキャンセル・再入力後に適用すると、古い結果で「筐体」へ更新されることを再現した。文字列の内容自体が正しくても、以前の入力に対する結果なので適用すべきではない。

## 修正

CoreとLIVEスナップショットに世代番号を追加し、入力イベント・設定・文脈・再変換・履歴再読込などの変更で更新する。適用時には既存の状態比較に加え、世代の一致を要求する。正常に推論結果を適用したときも世代を更新する。

世代は共有のAtomicU64から取得する。独立に編集されたengineのcloneや別engineが、同じ入力文字数と状態へ戻っても同じ番号を再利用しない。毎回の割り当ては行わず、原子的な番号取得と比較を追加した。番号を状態保存やユーザーの学習データへ書き込むことはない。

## 検証

- キャンセル・同一読み再入力のCore回帰テストは、修正前に失敗し修正後に通過した。
- 文脈を変更して元へ戻す場合、プライベート設定を変更して戻す場合も回帰テストで確認した。
- Core全242テスト、C ABI smoke、Swiftアダプタが通過。Clippyも既存の `chunks_exact_to_as_chunks` を除外して通過した。
- Q4同梱の修正後バンドルで実際に採点した結果を使用。文字追加、削除、Space、確定、キャンセル、キャンセル後再入力、文脈変更、プライベート化、文脈復元、プライベート設定復元の10通りで古い結果が表示アクションを返さないことを確認した。
- 古い結果を適用しない対照engineと、その後の確定アクションが一致した。新しい結果を実際に適用する正の対照、別engineの結果を拒否する確認も通過した。

モデルや採点重みは変更していない。推論結果の適用境界・回帰テストに加え、下記の全件再実行も行った。物理キー・InputMethodKitを通す操作の検証とは区別する。

## 修正後の全件再実行

修正したCoreを含む評価器を再ビルドし、Q4・現行の短文／長文設定で全10集合2,545件を再実行した。第一候補は1,576件、LIVEは1,571件で正解し、修正前と一致した。

各集合で第一候補の全出力、LIVEの全変更記録、worker status集計、第一候補・LIVEの正解数、表示候補・LIVE候補の正解数を照合し、すべて一致した。正解数だけの一致ではない。通常の評価手順で有効な推論を誤って拒否する差は見つからなかった。

`target/evaluation/live-generation-integration-20260909/` に再実行スクリプト、全入力・モデル・評価器のハッシュ、全件結果、比較スクリプトと検証JSONを保存した。

`target/evaluation/q4-live-generation-20260909/` に修正前ソース・QAアプリ、失敗再現ログ、テスト・ビルドログ、Swiftプローブ、修正後の実行結果とハッシュを保存した。モデルと履歴は利用者のものを使わず、評価用プロファイルだけで実行した。
