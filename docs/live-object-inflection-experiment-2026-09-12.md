# 目的語の後の短い単語を変換する試作

不採用。ソースを直前の採用版に戻し、QAアプリが採用版のままであることをハッシュで確認した。証拠は `target/evaluation/live-object-inflection-20260912/`。

採用版の不一致1,050件を再集計すると、正解がLIVE候補にある例が608件、そのうち正解一位でも適用されない例が21件あった。短いかな末尾の保護により「記憶をなくし」「力をいれ」などが漢字化されないことを確認した。

試作では、安定した前半が「を」で終わり、その前半を変更せず、2〜4文字の読み全体が辞書の単一語に一致し、送り仮名を維持する場合に適用を許可した。辞書探索はworkerでキャッシュする。Core260・FFI46とClippyが通り、実辞書の確認・キャッシュ・古い入力世代の拒否もテストした。動詞の品詞を直接確認する実装ではなく、「旅行を共に」の副詞も条件を満たす。

かな2,745件は1695→1701、正答から誤答0、誤答同士の変化3。ローマ字200件は全文入力後108→109、毎文字推論111→112で、逐次入力の他の出力と明示変換は一致した。診断21件と追加12例の毎文字推論33行は7→10で、正答の悪化はなかった。

しかし「流れをくみ」は期待する「汲み」ではなく「組み」に変わった。追加例の「言葉をあげる」も「上げる」となった。前者は全文完全一致の集計では誤答同士だが、かなで意味を保てていた箇所を不適切な漢字へ変える問題である。このため集計上の正答数だけで採用しない。

入力時点のトレースでは「言葉をあげ」の段階で「上げ」になった。別途採点したモデルの値では別候補が高く、辞書コスト込みの順位と食い違う。スコアは元の内部呼び出しそのものを記録したものではない。次は新たに許可する短い語についてモデル側の支持も検査し、辞書だけのフォールバックでその条件が迂回されないことを確認する。
