# モデルの支持を確認する短い語のLIVE変換

採用済み。全件評価、ローマ字200件の逐次入力、最終QA、遅延と署名を確認した。証拠は `target/evaluation/live-object-model-support-20260912/`。

## 変更

「を」に続く2〜4文字のかなを、前半と送り仮名を保った単一の辞書語に変換する試作では、「流れをくみ→組み」のような不適切な漢字化も生じた。辞書の一致だけでは採用しなかった。

今回は、実際のworker採点で選択候補がモデルの素の点数でも最上位の場合にだけ、新たな適用許可を記録する。許可は読み・文脈・選択候補に結び付ける。辞書だけの補正やモデル結果と異なる候補は、この許可を使えない。既存の適用規則は維持する。

辞書分割の検証結果はworkerでキャッシュする。追加のモデル呼び出しは行わず、既存の採点結果を使う。入力世代・候補集合・元の表示・文脈の検証も維持する。これは動詞の品詞を直接識別する実装ではなく、送り仮名を含む単一語の形状と辞書の読みを確認するもの。

## 確認した結果

- Core260・FFI46テスト成功、Clippy成功（既存の `chunks_exact_to_as_chunks` 警告のみ除外）。モデルの支持がない場合、不正な点数、別文脈、別候補、古い入力世代で許可が使われないことを確認。
- かな2,745件は1695→1698、改善3・正答から誤答0。明示変換は全出力一致。改善は「記憶を無くし」「腕力を活かし」「言葉を挙げる」の期待表記への一致であり、3件すべてが新たな意味理解を示すわけではない。
- 誤答同士の出力変化は1件。「一時期記憶を無くし」は期待表記「失くし」と一致しないため、改善には含めない。「流れを組み」「言葉を上げる」の問題は再発していない。
- ローマ字200件の全文入力後推論は108→109。かな集合の一部を別入力経路で再生したもので、独立した追加集合ではない。
- 最終QA187行（重複を除く163種類）は93→94、正答の悪化・誤答同士の変化0、明示変換は全出力一致。直接Enter確定は全行でLIVE表示と一致。基準187行は、同一FFIライブラリの確認済み153行と追加34行の再生を合わせた。

インストール・公証・公開はしていない。物理キー入力、InputMethodKit、実時間debounceは未検証。

## 最終確認

ローマ字200件の逐次入力は111→112。「言葉を挙げる」の1件が改善し、ほかのLIVE・明示変換出力はすべて一致した。

他のビルド・推論終了後、8例を前後交互に3回測定した。各回worker p50の中央値は23.68→24.91 ms、apply最大は0.021584→0.022750 ms。小規模な参考測定であり、一般的な速度優位や物理入力での遅延を示すものではない。
