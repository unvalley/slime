# 動詞と助動詞の構造による候補生成の試作

2026-09-14追記: 最新の通常版は [動詞・助動詞候補をLIVEに接続した採用版G](live-object-auxiliary-integration-2026-09-14.md)。以下はこの調査・採用時点の記録。

未採用。2026-09-14。採用済みの本文支持付き Space 版を保持し、converter の候補生成 API だけを隔離して試作した。LIVE の変換結果を改善した段階ではない。

## 候補が落ちる理由

固定済み辞書診断の「かいたい」は、最短経路が「解体」5477、「買いたい」7026、「飼いたい」7999。正解の「飼いたい」は N-best の 3 位に存在するが、単一区間の首位に対する複数区間候補の上限 2500 を、差 2522 が超えるため通常候補から外れる。現在の LIVE 要求に「飼いたい」がないことは別の実要求トレースでも確認済み。

## 品詞の根拠

辞書抽出元と同じ Mozc revision `3f235b4eb6fcff7d14ef5f0fb8ee56de7ee4c732` の [id.def](https://raw.githubusercontent.com/google/mozc/3f235b4eb6fcff7d14ef5f0fb8ee56de7ee4c732/src/data/dictionary_oss/id.def) を取得した。動詞・自立・連用形は 31 ID、助動詞は連続した ID 29〜267。「買い」「飼い」の動詞エントリは 829、「たい」の助動詞エントリは 152。名詞「買い」や名詞「会」とは区別できる。取得ファイルと抽出結果のハッシュを保存した。

## 試作

`Dictionary::verb_auxiliary_candidates` は 2〜8 文字の読みを二つに分け、実際の辞書エントリで動詞連用形と、表記が読みそのものの助動詞をつなぐ。BOS・語間・EOS の接続コストと文脈順位付けを使い、同じ表記は最小コストへまとめ、返す候補を最大 16 件に制限する。対象単語の決め打ち、通常候補窓の拡大、モデル呼び出しの追加はしていない。

実辞書で「買いたい」7026・「飼いたい」7999 を回収できた。「解体」「回タイ」はこの構造候補には含まれない。構造があることだけで入力意図が正しいとは判断しない。

## 検証と残作業

converter の 69 テストが成功、既存の 1 テストは ignored。Clippy 成功（既存の `chunks_exact_to_as_chunks` 許可）。追加テストは名詞・動詞・助動詞の区別、重複と最小コスト、出力数・読み長の制限、実辞書での候補回収と接続コストを確認した。

試作を LIVE に接続する前に、worker でのキャッシュ、既存候補との統合、構造に限定した採点開始条件、モデル支持に基づく長さ変更・適用許可、速度と広い精度比較が必要。候補を回収しただけで「買いたい」が表示されるとは主張しない。

検証後は converter ソースを元の内容へ戻し、採用済み FFI・neural ソース・アプリ・評価器も採用時のハッシュと一致することを確認した。証跡は `target/evaluation/live-object-morphology-20260914/` の `converter-candidate.rs`、`morphology-evidence.json`、`tests.log`、`clippy.log`、`restoration.json`。
