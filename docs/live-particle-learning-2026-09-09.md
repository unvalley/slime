# 助詞付きの文脈学習をLIVEへ反映 — 2026-09-09

前段の[助詞付きSpace変換](context-particle-conversion-2026-09-09.md)に続き、
LIVEでも「食事」の後に学習した「箸」を「箸を」「箸に」などへ反映するようにした。
ローマ字入力とモデルタスクAPIを使った同梱物の確認で、9種類の助詞すべてが改善した。

## 境界の扱い

文脈履歴から助詞付き表記を優先候補として渡し、LIVEの既存の辞書経路とコスト差の条件で検証する。
表示に採用された助詞付き学習候補だけを、モデルタスクの上書きから保護する。
候補を作るだけで無条件に表示したり、モデル処理を抑制したりはしない。

助詞と見える文字が語の途中の場合もあるため、この学習による表示では文節を固定しない。
`hashimo` で「箸も」を表示した後、`to` を続けると「橋本」へ切り替わる。
学習由来の短い表示を次の読みへ固定的に延長しない、前段の保護も助詞付き表記に適用した。

## 確認結果

更新アプリの同梱dylib・同梱モデルを使い、新しい検証用ディレクトリの履歴を読み込んだ。
必要なモデルタスクはcreate/run/applyのAPI経路で実行した。9種類の助詞付き入力は、
変更前の「橋は」「橋を」「橋に」などから、同期LIVEの「箸は」「箸を」「箸に」などへ変わった。
「は下」になっていた `hashimo` も「箸も」になった。9ケースとも学習済み表示を上書きするタスクは作られない。
`hashimoto` は変更前後とも最終的に「橋本」だった。

プライベートモードでも同じ10ケースを実行し、9種類の助詞で学習した「箸」を参照せず、
モデルタスクも作られないことを確認した。いずれの読出し検証でも履歴ファイルの内容は不変だった。

Core全238テスト、clippy、C ABI smoke、Swift adapterが成功。
clippyは既知の別箇所の `chunks_exact_to_as_chunks` のみ許可した。
更新アプリの署名検証も成功した。追加のCoreテストは9種類の助詞、モデル上書きの保護、
非固定の文節境界、「橋本」への入力継続を対象にしている。

## 成果物と範囲

`target/evaluation/live-particle-20260909/` に変更前ソース・アプリ、今回だけの差分、
テストログ、通常・プライベートの同梱物の結果、最終ハッシュを保存した。
これは文脈学習の改善であり、一般コーパスの正解率や速度の改善を主張するものではない。
複数の助詞や後続文全体への一般化は未確認。インストールとInputMethodKitの実キー入力も未実施である。
