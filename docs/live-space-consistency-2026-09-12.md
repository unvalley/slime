# Experimental LIVE-to-Space agreement — 2026-09-12

The adopted guided-joint LIVE fix exposes a separate explicit-conversion problem: a correct LIVE surface can become incorrect on Space. An audit of the fixed2745-row evaluation found77 correct-LIVE/wrong-Space rows,45 wrong-LIVE/correct-Space rows and110 other differing rows, counting only records with an applied LIVE change. These are exact expected-string comparisons, not semantic judgments or all LIVE results. Unconditional LIVE retention would therefore regress existing results.

A diagnostic reconstructed explicit candidate requests and scored232 differing rows with the same model. Among144 readings shorter than20,139 reconstructed raw winners matched the recorded Space result. The mismatches include numeric surfaces; a raw scoring audit omits existing application/gating behavior and is not the production boundary; the five mismatches are excluded from policy projections.131 short rows contain the preceding LIVE surface in the rankable pool. Examining margins is development analysis, not held-out validation.

The candidate experiment only retains the immediately preceding validated LIVE worker surface when the reading has8–19 characters, the surface is present in the explicit rankable list, Hiragana and digit sequences are preserved, its neural likelihood exceeds the current explicit winner, and their combined-score difference is at most0.2. It reuses the same scores; no additional model inference is introduced. The length restriction avoids short ambiguous words with little context, and the surface guards limit this experiment to compatible written alternatives. These restrictions were chosen after examining development examples and require separate validation.

Core now records the generation at which a LIVE result was applied. The current_live_neural_surface getter requires that generation, reading and rendered display to remain unchanged, with LIVE enabled, composing state, no pending romaji and no private/suppressed mode. The FFI captures this surface immediately before Space under the same exclusive handle borrow. Input, preference or external-context changes invalidate the getter through the existing generation changes. The old LIVE extension behavior continues to use the original reading/surface fields. The captured prior is local to one synchronous Space operation and is not persisted.

The experimental runtime flag defaults false on model load and is available only through a Rust evaluator setter and --explicit-live-agreement. No C header, Swift bridge, app policy or installed IME enables it. The ordinary explicit ranking helper was consolidated without changing its scoring/gating behavior, and both ordinary and experimental recombination paths can consume the optional prior. Long-reading recombination remains unchanged.
