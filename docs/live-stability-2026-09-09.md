# LIVE変換の長文表示安定性 — 2026-09-09

後続の[長い読みのSpace変換](explicit-ranking-2026-09-09.md)で、明示変換の追加改善を記録している。

## 変更

[前段の候補回収改善](conversion-quality-2026-09-09.md)を基準に、長文の入力途中で
変換済みの後半がまとめてかなに戻る挙動を改善した。

先頭の文節を固定した後、残りの読みが曖昧になると、従来はその残り全体をかなで表示していた。
新しい処理は、残りの読みが10文字以上で、1文字のかな追加であり、上位候補が既存の変換部分を
引き続き支持する場合に限り、直前の表示に入力文字を足す。数字を含む表示、脆弱な接頭辞、
変換部分が2文字未満の場合は対象外とする。新たな辞書探索や永続キャッシュは追加していない。

例えば「資料などをすべて破棄したことが明かされたため、再販は不可能なじ」の次に「ょ」を
入力したとき、以前は「資料などを」以降がかなに戻った。修正後は「破棄したこと」などの
表示を保つ。後続キーでは引き続き残り全体を探索し、確信のある変換で更新できる。

表示の維持を変換の確定と取り違えないよう、`SuffixContinuity`状態を設けた。
次のキーでの同期探索にも、維持した表示ではなく未解決の読みを基準として渡す。
モデルへ渡す基準文字列では残りを未解決の読みとして扱い、固定済み接頭辞も含む補正が
必要な場合の探索範囲を保っている。初期試作でこの補正範囲が狭まる回帰を検出し、
既存テストが元の範囲と補正結果を確認できるようにしてから採用候補とした。

## 評価

モデルは前段と同じ同梱相当のzenz v3.2 small Q3_K_M。モデルの重みや採用閾値は変更していない。
開発にはJWTDの失敗例を使い、UD testとAJIMEEで個別の語句に合わせた調整は行っていない。
個人辞書・入力履歴は読み込んでいない。

| 評価集合 | 同期LIVEの書き戻し文字数 | モデル適用後の正解数 |
| --- | ---: | ---: |
| JWTD 400件 | 7,694 → 7,298 | 198 → 198 |
| UD dev 331件 | 変化なし | 277 → 277 |
| UD test 323件 | 変化なし | 276 → 276 |
| AJIMEE 200件 | 3,755 → 3,639 | 146 → 147 |

同期LIVEの最終完全一致正解率は全4集合で変化なし。数字の混入、かなへの全面的な戻り、
固定可能な文節の書き戻しの各集計も変化なし。モデルで以前正解だった項目の喪失は0件。
Space変換の正解数も前段と同じだった。

書き戻しには必要な変換も含まれるので、回数や文字数だけで品質は判断できない。
JWTDでは17項目で文字数が減り、1項目で9文字増えた。AJIMEEでは6項目で減り、2項目で
計11文字増えた。全項目が改善したわけではない。

AJIMEEの新しい正解はサッカーの文脈の「ボールを奪取する」。以前はモデル適用後も
「ボールをダッシュする」だった。表示継続後も文脈補正できることを確認した。

## 遅延

表示を次の同期探索へ戻す試作v3は、3回の交互測定でAJIMEEのp95が4.35 → 6.87msに
増えたため採用しなかった。最終版v4は表示を探索の確信の根拠にしない。

同じApple M3でビルド・モデル実行終了後に前後を交互に3回測定した。
各回のパーセンタイルの中央値は以下。IME全体の起動時間や描画遅延ではなく、
同期LIVEのキー入力処理時間である。

| 評価集合 | p95 ms 前 → 後 | p99 ms 前 → 後 |
| --- | ---: | ---: |
| JWTD | 3.652 → 3.610 | 12.421 → 12.219 |
| UD dev | 0.092 → 0.091 | 0.135 → 0.134 |
| UD test | 0.090 → 0.089 | 0.129 → 0.127 |
| AJIMEE | 4.328 → 3.968 | 17.594 → 17.556 |

最終版では試作のp95増加を解消できた。ただし長文の最大処理時間は約54msで、
入力の全区間が16ms以内になったわけではない。

## 検証と再現

成果物は `target/evaluation/live-stability-20260909/`。
`core-before.rs`は前段終了時のソース、`implementation.patch`は今回のCore変更だけの差分。
`datasets.json`に入力パス、`source-binaries-sha256.txt`にソースとRelease実行物のハッシュを記録。
`*-candidate*`と`*-v3*`は試作の評価。`*-accepted*`が探索へのフィードバックも抑えた最終版。

Rust workspaceは449テスト通過、既存のignore指定2件。最終変更後もCoreの233テストを再実行した。
長文表示の維持、候補の支持がない場合の除外、数字・複数字入力・脆弱な接頭辞の除外を検証した。
既存の全文補正テストは、表示だけの期待値を更新し、探索範囲とモデル結果適用の期待値を維持した。
Release共有ライブラリを通すC ABI試験とmacOS Swiftアダプター試験も通過。
Clippyは前段と同じ既知の`chunks_exact_to_as_chunks`だけを除外し、全targetで`-D warnings`を通過した。

インストール済みIMEの置き換えや配布は行っていない。他IMEとの比較や実アプリでの長時間入力は
未検証であり、この評価だけで「日本で随一」とは判断できない。
