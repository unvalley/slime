# 長文の文脈候補の保護修正（2026-09-09）

長文の候補を16件に広げた後、文脈辞書で優先された11〜16位の候補にContext注釈が付かない問題を修正した。生成・モデル要求は16候補を見ていたが、注釈生成だけ10候補を参照していたため、文脈で優先した候補がモデルで並べ替え可能になっていた。

候補上限の判断を共有関数にまとめ、候補生成・ランキング要求・文脈注釈で同じ上限を使うようにした。20文字以上16候補、その他10候補の採用済み方針自体は変更しない。

追加した回帰テストは、通常10候補に含まれない長文表記を文脈ルールで先頭へ昇格させ、Context注釈、ランキング要求からの除外、順位を逆順に適用しても先頭を維持することを確認する。修正前にはNone注釈で失敗し、修正後に成功した。

コア240件、Clippy、Cスモーク、Swiftアダプタが成功。モデル同梱QAアプリを再ビルドし、署名を検証した。さらに同梱dylibとモデルを使うSwiftプローブで、検証専用の文脈ルール入り辞書を読み込み、Space変換後にもContext注釈が残ることを確認した。利用者の辞書・履歴は使っていない。

資料は `target/evaluation/long-context-protection-20260909/`。`reproduction.log` に修正前の失敗、`core-tests-final.log` などに検証結果、`ContextProbe.swift` と `bundled-probe.log` にモデルを含む境界検証を保存した。旧QAアプリは `Slime-before.app`。ローカルad-hoc署名で、実機キー入力・インストール・公証は未確認。
