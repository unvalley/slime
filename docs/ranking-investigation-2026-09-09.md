## 結論

通常のモデル重みを0.2から0.4へ一律に上げる変更は不採用。製品のソースと設定は変更していない。
長い対象に使う重み0.6と各採用マージンは固定した。モデルは前段と同じQ3_K_Mである。

| 集合 | LIVE正解数 前 → 試験 | Space正解数 前 → 試験 |
| --- | ---: | ---: |
| JWTD 400 | 198 → 198 | 150 → 184 |
| UD dev 331 | 277 → 280 | 279 → 283 |
| UD test 323 | 276 → 277 | 271 → 265 |
| AJIMEE 200 | 147 → 146 | 124 → 144 |

LIVEの件数差だけでは見落とす悪化がある。UD devは8項目改善・5項目悪化、UD testは
6項目改善・5項目悪化。AJIMEEでは改善0・悪化1だった。ここでの悪化は、同期Coreとの
比較ではなく、現在採用中のモデル結果が正解だった項目を失うことを指す。

開発集合でのSpaceの増加だけを見れば有望だったが、UD testの6件減少とAJIMEEのLIVEの
後退を受け、共通設定の変更は止めた。今後は明示的な全文変換と自動的な部分変換を分けて
調べる。長文に限った方針が有効かは、この比較だけでは証明していない。
