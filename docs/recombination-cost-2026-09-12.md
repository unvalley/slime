# 再結合の探索費用を分離（2026-09-12）

精度向上用の再結合候補を増やす前に、既存の辞書処理をReleaseで測定した。製品ソース・QAアプリは変更していない。

長さ4層から15件ずつ選んだ既存60件を使用し、辞書の実際の入力に合わせてカタカナをひらがなへ正規化した。各入力で通常候補探索、通常経路探索、再結合全体を3回測定し、操作順を反復ごとに回転した。各操作の候補表記・コスト・順序のハッシュと件数が反復間で一致した。辞書初期化と結果ハッシュ計算・出力は計測外。通常経路探索の測定は結果を表記・コストへ投影する処理も含む。

| 操作（20文字以上30件） | 入力別3反復中央値のp50 | 同p95 |
| --- | ---: | ---: |
| 通常候補16件探索 | 6.80ms | 13.31ms |
| 再結合元の16経路探索 | 6.32ms | 12.36ms |
| 最大4件の再結合全体 | 7.18ms | 14.17ms |

異なる計測の中央値の差は、再結合だけの厳密な時間ではない。それでも元の探索に大きな費用があることが分かる。通常候補は表記を分散させる探索、再結合元は従来の経路探索を使っているため、単純な共通化は出力保持を保証しない。

CoreはSpace候補生成後、ランキング要求時に候補を探索し直し、ランキング適用時にも要求を再構築する。次に検証すべきは、変換状態の一致を確認したうえで要求時の結果を再利用する方法。古い状態の候補や個人辞書変更後の候補を適用しないことを保証し、全件の出力一致と統合速度で検証する必要がある。現時点では未実装。

資料は `target/evaluation/recombination-cost-20260912/`。プローブのソースと固定バイナリ、入力・正規化後読み、全540測定、解析、各ファイルのハッシュを保存。初回の未正規化カタカナによる測定は無効として別名に保存し、集計から除外した。今回の数値は辞書処理だけであり、モデル推論・FFI・Swift・UIや実機キー入力の時間ではない。
