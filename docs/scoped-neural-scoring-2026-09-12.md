# Scoped interactive scoring — 2026-09-12

The model scorer now provides `with_interactive_scoring`, a synchronous callback scope that lazily allocates its context and batch on the first score request, reuses their allocation for later requests, and drops them at scope exit. Each decode still starts by clearing KV state and batch data. A scoring error discards the work arena. The callback may choose not to score, in which case no arena is created. This is no cross-thread or persistent cache.

Only the opt-in targeted-recombination FFI branch uses the new scope. Ordinary Space/LIVE continue through their existing scorer entry points; those share an extracted context-construction helper with identical settings. The app's default policy is unchanged.
