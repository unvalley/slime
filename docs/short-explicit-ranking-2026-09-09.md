# 短文の明示変換重み検証（2026-09-09）

短文全体を0.2から0.25に変更する案は採用しない。20文字未満903問で完全一致675→678、改善9・悪化6となり、UD testは271→269に低下した。

| 集合 | 問題数 | 現行0.2 | 実験0.25 | 改善 | 悪化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| JWTD | 105 | 44 | 46 | 2 | 0 |
| UD dev | 331 | 279 | 280 | 4 | 3 |
| UD test | 323 | 271 | 269 | 1 | 3 |
| AJIMEE | 92 | 64 | 66 | 2 | 0 |
| 追加JWTD | 52 | 17 | 17 | 0 | 0 |

既存1,454問から入力長だけで抽出した。`live_neural_evaluate` に `--explicit-long-lambda 0.25 --explicit-min-characters 1` を渡し、この抽出集合の明示変換だけに適用した。LIVEの重みは変更しない。比較対象は同じソースの既存評価結果で、20文字未満の現行重みは0.2。

悪化6問はすべて読みが2文字だった。「針→張」「説→節」「付き→付」「住み→済」「美穂→美保」「医師→意思」。短い語は文脈を含めても曖昧で、モデル重みの一律引き上げを支持しない結果となった。

一方、JWTD・AJIMEEの改善4問は15〜19文字で、「整体パーツ→生体パーツ」「感じを和訓→漢字を和訓」「武道館公園→武道館公演」など。11〜19文字で変化した他の出力には、依然として誤りが残るものもある。この長さの範囲への限定適用は未採用であり、別の入力集合で検証する必要がある。今回の結果を見て範囲を選ぶこと自体が調整なので、同じ集合だけで有効性を主張しない。

再現資料は `target/evaluation/short-explicit-20260909/`。`manifest.json` に集合数、各集合JSONに抽出入力、`*-025.json` に実行結果、`analyze.py` と `comparison.json` に比較手順と全変更を保存した。

製品設定とQAアプリは変更していない。採用済みの20文字以上0.45、その他0.2を維持している。

## 別の中程度入力200問による検証

直近の400問と追加200問のID・原文・読みを除外し、10〜19文字の1,140問から固定seedによるSHA-256順で200問を抽出した。抽出を両設定の実行前に行い、同じバイナリで重み0.2と0.25を比較した。

完全一致は102→102、改善1・悪化1だった。「無資格マッサージし問題→無資格マッサージ師問題」は改善したが、「に進行して終止するもの→に進行して終始するもの」が悪化した。他3問の出力も変わったが、期待出力への完全一致には至らなかった。LIVE変更トレースとworker status集計は同一。

この追加集合では純改善を確認できなかったため、中程度入力に限定する0.25も採用しない。閾値をさらにこの200問へ合わせる調整は行わず、正解候補の生成・保持の問題を次の調査対象とする。

再現資料は `target/evaluation/medium-explicit-20260909/`。`select.py`・`manifest.json` に選択条件と入力ハッシュ、`items.json` に抽出集合、`weight-*.json` に全件結果、`analyze.py`・`comparison.json` に差分を保存した。元コーパスは以前の評価で参照済みであり、新規コーパスやモデル学習から独立したholdoutではない。
