# Surface-guided dictionary paths — 2026-09-12

`Dictionary::conversion_for_surface` reconstructs a path for an exact requested surface. For connected dictionaries, it uses the same dictionary prefix entries, candidate-list synthetic entries and literal unknown edges as menu search, but retains only edges matching the remaining target surface. State identity is reading boundary, target-surface byte position and right POS. Equivalent states keep the lower connected cost; each reading boundary is bounded to64 states. Future buckets may replace their arena slots because no descendant can reference them before their boundary is processed. Node storage reuses the existing bounded-size NBestNode with a parallel surface-position array.

Input is bounded to128 reading characters and2,048 surface bytes. Empty readings/surfaces return None. Costs include word entries and exact POS connections including BOS/EOS, but beam pruning means the returned path is not guaranteed globally cheapest. Heuristic dictionaries retain their existing bounded16-path search. This is dictionary-supported reconstruction, not arbitrary text generation.

The two motivating source paths match their original costs59,620 and60,599. A second test recovers up to16 distinct paths for each of six readings covering ordinary compounds, numbers, literal Latin text, punctuation and emoji, checks both reading/surface segment concatenation, and requires no cost increase in those fixtures. These finite cases do not prove all-path equivalence. Invalid surface, empty and oversized-reading boundaries are also tested.

An alternating component benchmark (32 sequences per mode, excluding two warmups) measured median9.270ms for the old targeted operation and0.358ms for two guided source recoveries. The former includes the final recombination graph; the latter does not, so these are not identical complete operations. Both source costs were checked each time. The driver and binary were frozen and its temporary example source removed.

The existing targeted recombination API now obtains its two source paths through this guided API, then uses the unchanged observed-edge recombination graph. Its sources are still checked against the current Core request before use. Ordinary conversion and ordinary recombination paths are unchanged; this API is used only by the evaluator-opt-in two-stage ranking path. The guided search can find a different segmentation or a source absent from the old distinct16 beam, so output parity must be measured, not assumed.

Integrated tests pass: converter67 plus one preexisting ignored, Core267, neural FFI53. Clippy passes with the existing chunks allowance. Full comparison over3,945 rows completed against the previous targeted-neural-integration reports, including its extra400 long readings. That full-report baseline predates scoped context allocation reuse, so the result establishes combined output parity rather than attributing changes between the two optimizations. No changed outputs require the planned scoped-only attribution rerun.

The optimized search is retained on the experimental path; no universal speedup claim is made. No adoption or app rebuild has occurred.
